# xyzaishell

在一个窗口里使用 SSH 终端和 AI 助手：左侧连接服务器，右侧讨论问题或启动终端任务。AI 的命令会显示在同一个可见终端中，风险或无法判断的命令需要逐条授权。

## 1. 下载与安装

前往 [GitHub Releases](https://github.com/yanch123/xyzaishell/releases)，选择 **v0.1.0 预发布测试版**，先阅读该版本的已知限制，再展开 Assets 下载安装包：

- **Windows x64**：下载 `.exe` 安装包，运行安装向导。程序需要 Microsoft WebView2；缺少运行时的电脑在安装时可能需要联网。
- **Ubuntu x64**：下载 `.deb`，在文件所在目录使用 `sudo apt install ./实际文件名.deb` 安装，再从应用菜单启动。目标系统为 Ubuntu 22.04／24.04，需要系统 GTK／WebKitGTK 运行依赖。
- 同一 Release 提供源码压缩包和 `SHA256SUMS.txt`。普通使用请选择安装包；下载后可核对 SHA256，校验和不等于代码签名。

**这是预发布测试版。Windows 安装包未签名，可能出现发布者或 SmartScreen 提示。Windows 10／11 实机、Ubuntu 完整桌面使用流程和外部模型供应商兼容性尚未完成验证。** 遇到安全警告时先停止并核实来源；请先在测试服务器上使用，不要直接用于关键生产操作。macOS、ARM、其他 Linux 发行版暂不在支持范围内。

## 2. 配置模型

准备一个支持 OpenAI 兼容 Chat Completions、流式响应与工具调用的服务，以及它的 Base URL、API Key 和模型名称。

1. 启动程序，打开设置，查看显示的模型配置文件路径。
2. 将[完整模型示例](config/examples/model.example.toml)复制到该路径，或创建下面的最小 `model.toml`。把三个占位值替换为服务提供方给出的实际值：

   ```toml
   schema_version = 1

   [model]
   protocol = "openai_chat_completions"
   base_url = "https://api.example.invalid/v1"
   api_key = "REPLACE_WITH_LOCAL_API_KEY"
   name = "REPLACE_WITH_PROVIDER_MODEL_NAME"
   ```

   `base_url` 是 API 根地址，通常以 `/v1` 结尾，不要追加 `/chat/completions`；模型名称填写在 `name` 字段。以上占位配置不能直接连接。
3. 保存文件，点击“重新加载模型配置”，核对接收方与模型，并确认聊天发送范围。随后可以“测试连接”；这只测试最小流式聊天请求，不证明工具调用兼容。

默认文件位置：

- Windows：`%APPDATA%\xyzaishell\model.toml`
- Linux：`$XDG_CONFIG_HOME/xyzaishell/model.toml`；未设置有效的配置目录时使用 `$HOME/.config/xyzaishell/model.toml`

要使用其他文件，在应用启动环境中设置 `XYZAI_MODEL_CONFIG`，值必须是本机文件的**完整绝对路径**，例如 `C:\Users\你的用户名\.config\xyzaishell\model.toml` 或 `/home/你的用户名/.config/xyzaishell/model.toml`。改变此变量后重启应用；“重新加载”只读取本次启动选定的路径。`OPENAI_API_KEY` 等变量不会覆盖文件内容。

API Key 在 TOML 中明文保存。请使用私有本机目录，不放入同步盘或共享目录；Linux 私有目录权限设为 `0700`、文件为 `0600`，Windows 文件须通过当前用户／系统管理员权限检查。不要把 Key、SSH 密码、私钥或整份配置粘贴到聊天里。模型地址默认要求 HTTPS；本机回环 HTTP 需在配置中显式启用。

## 3. 登录 SSH 服务器

点击连接入口，填写主机、端口（默认 `22`）和用户名，选择密码或本机私钥认证。私钥需填写绝对路径；加密私钥还需口令。确认仅本次连接使用凭据后，点击“连接服务器”。

首次连接会要求核验主机密钥指纹，请通过可信渠道核对后再信任。指纹变化时应先确认服务器是否更换了密钥。

常用服务器可通过“管理已保存的 SSH 档案”新建档案，填写后点击“保存档案”，再“连接已保存档案”：

- 档案保存连接信息；只有明确选择保存凭据，才保存密码或私钥口令。
- Windows 使用当前用户的系统保护存储；Linux 需要可用、已解锁的 Secret Service 安全存储。保存失败不会自动回退到明文。
- “会话内存模式”会影响全部档案，移除持久凭据引用，退出后需要重新填写凭据；当前界面不能直接切回持久模式，切换前请确认。

一个实例连接一台服务器；连接多台服务器时启动多个实例。左侧终端可手动输入，私钥文件不会发送给模型。

## 4. 右侧对话与终端任务

**文字聊天**用于讨论和规划，只发送你主动发送的消息、当前聊天历史及聊天行为说明，不自动读取终端或执行命令。可以新建多个对话。

需要 AI 实际操作服务器时：

1. 先连接 SSH，再在右侧切换到“执行终端任务”。
2. 输入具体任务，点击“核对并开始执行”。
3. 核对模型接收方、SSH 目标与数据范围，确认左侧已回到可输入命令的 Shell，选择“同意并开始本次任务”。本次指令、模型分析、拟执行命令及本次运行开始后收集的有限终端输出会发送给模型服务；服务可能记录内容或收费。
4. 查看准确命令卡片。少量精确匹配的检查命令（如 `pwd`、`whoami`）可以自动发送，其余需点击“仅批准这条命令”。批准只对当前连接、当前任务的这一条命令有效。
5. **每次写入后都要检查左侧终端**。当前版本不能可靠判断远端命令完成；确认终端可接收下一步命令后，点击“确认就绪并继续分析”。发送成功或 AI 流程结束不代表远端任务成功。

多个对话共享同一个远端终端，同时只有一个 AI 任务可以写入。手动输入始终可用，请自行避免与 AI 同时输入。“停止 AI 任务”仅阻止后续步骤，不撤回已发送的命令，也不自动发送 Ctrl+C；需要中断远端程序时使用左侧独立的“发送 Ctrl+C”。断线或发送结果未知时先核实远端状态，不要盲目重发命令。

## 5. 为任务填写密码或令牌

每个 AI 任务使用独立的本机秘密文件。需要凭据时，模型只提出字段名和用途：

1. 点击“准备本机秘密文件”，在本机编辑器中打开界面显示的文件，填写对应字段的 `value`。
2. 保存后点击“重新加载已填写状态”。模型只收到字段名、是否已填写等信息，不会得到秘密值或本机文件路径。
3. 需要输入远端时，先确认终端正在等待正确程序的密码输入，而不是普通 Shell 命令行。选择字段、填写用途并确认目标与回显风险，点击“核对本次秘密输入动作”，最后在卡片上批准本次输入。

秘密输入仅支持单行值并追加一次 Enter，不用于拼接 Shell 命令。修改／重载文件或更换连接后需重新核对。任务文件是受限权限的明文文件，编辑器备份和远端程序仍可能记录秘密；脱敏不能保证识别所有变形或未知秘密。不要在聊天或用途栏填写秘密值。详见[任务秘密操作说明](docs/v0.1/11-user-guide.md#5-任务中的密码和令牌)。

## 6. 可选的本机历史

聊天历史默认关闭，每次启动需在设置中明确启用。启用后将脱敏文字保存在本机明文数据库，不保存原始终端输出或可重放的授权。

恢复历史只恢复文字，不会重连 SSH、启动模型或重发命令。关闭历史只停止新增保存，不删除已有记录。单独移除记录需再次确认，逻辑删除不可恢复，也不保证物理擦除。存储位置与详细操作见[使用指南](docs/v0.1/11-user-guide.md#6-保存和恢复历史)。

## 常见问题

- **读不到模型配置**：核对设置中显示的路径、TOML 字段、文件权限，以及 `XYZAI_MODEL_CONFIG` 是否为绝对路径。修改环境变量后重启。
- **能聊天，不能执行终端任务**：先确认已连接 SSH、没有其他任务占用终端；模型服务还必须支持所需的流式工具调用，聊天测试通过并不代表兼容。
- **保存 SSH 凭据失败**：检查系统安全存储是否可用、是否已解锁。也可使用仅本次连接；不要反复覆盖保存结果不确定的档案，先重新读取状态。
- **AI 停下来等待确认**：查看左侧终端，处理正在运行或等待输入的程序，再确认 Shell 就绪。不要把等待当作已经成功。
- **能传文件或操作本机吗？** 当前只通过 SSH 终端操作远端，不提供 SFTP、文件上传下载、本机 PowerShell 或 WSL。

更多操作说明见[完整使用指南](docs/v0.1/11-user-guide.md)。反馈问题请提供应用版本、系统版本、脱敏错误码和复现步骤，不要上传真实 Key、密码、私钥、任务秘密文件或包含秘密的截图。
