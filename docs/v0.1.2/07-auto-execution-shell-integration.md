# 07 — 自动执行与当前 Shell 集成

状态：已明确当前 Shell 临时 hooks 的方向，仍是待实施设计；协议、兼容矩阵与风险规则未冻结。本轮只修改文档，不安装 hooks 或执行真实命令。

## 1. 目标及基线差距

用户启动终端任务并完成所需数据授权后，普通命令在受支持、就绪且关联清楚的当前 Shell 中连续自动执行；危险命令才进入风险批准，无法判定的命令保持“未知风险”，不能伪装普通命令。正常命令结束不要求用户每条点击“Shell 已就绪”。异常恢复时仍可能需要人工处理。

当前 [execution.rs](../../crates/xyz-core/src/execution.rs) 只把少量精确字符串列为自动执行，其他命令要求批准；[agent.rs](../../crates/xyz-core/src/agent.rs) 在命令之后仍依赖人工就绪继续。[v0.1.1 日志集成](../v0.1.1/02-architecture.md)使用干净 Bash 子 Shell，日志事件不作为执行依据。达到本版目标需要风险分类、Shell 生命周期与执行状态机共同调整，不能只移除一个 UI 按钮或直接信任旧日志记录。

已选择的路线：在当前交互 Shell 中临时安装顶层命令生命周期 hooks，优先支持 Bash，保留已有 alias、function、prompt 和 hooks，不修改 `.bashrc`、`.profile` 等启动文件，不另开干净子 Shell，不创建隐藏 SSH exec 通道。具体 hook 组合和覆盖版本须经验证后确定。

## 2. 首次安装的就绪边界

SSH 已认证／PTY 已建立只证明传输可用，不证明前台就是空闲 Bash：可能仍处于 OTP、登录菜单、密码提示或启动程序。不能一连接就盲发版本探测或 bootstrap，也不能把提示符形状、静默时间或普通终端文字当作充分证据。

- 若已有受支持集成契约能识别当前 Shell 身份、版本、代次及空闲点，可在该契约边界进入安装流程；契约的识别机制仍待实现评审。
- 否则首次启用要求一次明确确认：“当前已进入空闲的受支持 Bash 提示符”。这只确认本次安装时机，不是每条命令的批准，也不自动批准危险命令。
- 安装通过同一个可见 PTY 进行；只在上述边界执行必要的能力核对与临时 hook 注册。匹配握手只确认集成身份和能力；还需当前 Shell 的就绪证据，不能握手一到就派发 AI 命令。
- 安装超时、输出异常、用户取消或状态变化时停止，不自动重复注入。再次尝试先重新核对当前前台状态，不能将上一轮 bootstrap 当作可安全重放的普通文本。

## 3. 保留当前环境与兼容性

接入只修改运行时必要的 hooks／应用命名空间状态；不清空历史、不禁用现有启动配置、不切换工作目录或用户、不替换已有 prompt。原有 hooks 的顺序、退出码语义、字符串／数组形式和动态修改都要纳入验证，不能简单覆盖 `PROMPT_COMMAND` 或 trap 后声称兼容。

| 环境 | 本期目标行为 |
| --- | --- |
| 已验证版本的交互 Bash，无冲突 hooks | 支持临时接入与连续普通命令执行 |
| Bash 带 prompt 插件、已有 hooks／trap | 先验证组合与恢复；不能安全组合就明确“不兼容”，保留手动终端 |
| zsh、fish、其他 Shell 或版本未验证 | 显示不支持／未验证；不自动换成 Bash 或安装兼容脚本 |
| 登录菜单、OTP、密码提示、前台交互程序 | 不安装、不把输入送入未知接收程序 |
| 嵌套 Shell、`sudo -s`、`su`、tmux、远端再次 SSH | 不假设 hooks 及身份自动继承；进入未知／人工处理，重新核对后再接入 |

停用只尝试移除仍由应用拥有的 hook 片段，不能覆盖用户此后改动。移除也需要当前 Shell 的安全空闲点；失去该边界时只停止宿主自动派发，不盲发清理命令。Shell 退出后临时状态自然消失。不能完整恢复时给出明确说明，不承诺任意插件组合的无副作用恢复。

## 4. 生命周期与连续执行

拟议状态：未集成 → 待首次就绪 → 安装中 → 就绪 → 执行中 → 前台已返回／等待就绪 → 就绪；另有待风险批准、需交互、未知、已断开。不把等待批准等同于 Shell 忙碌，也不把 SSH 在线等同于就绪。

1. 宿主准备一个动作，绑定任务／运行、不可变命令、连接代次、Shell 实例及当前状态。
2. 本机风险策略确定普通、危险或未知；危险必须有该动作的有效批准，未知先核对或人工处理。
3. 只有宿主验证仍就绪且动作未过期，才通过同一 PTY 派发；写入成功仅表示已发送。
4. hooks 自报顶层命令 begin、匹配 end、返回码及必要关联信息。宿主核对顺序和当前动作后记录 `command_completed`，此时只知道前台返回。
5. 已有 `PROMPT_COMMAND`、prompt hooks 或 `PS1` 展开仍可能执行／阻塞甚至进入交互；只有到达经验证的集成就绪边界、获得独立 `shell_ready` 证据后才允许下一次输入。握手、end 或退出码均不能单独替代它。
6. 就绪后重新准备并检查下一动作；不沿用任意旧动作或已消费批准，也不需要正常路径每条再次人工确认。无法可靠区分完成与就绪的 hook／prompt 组合应暂停或标为不兼容，具体就绪机制须实测后确定。

begin 不证明业务已开始成功，end 只表示所集成 Shell 报告该顶层前台命令返回；返回码 0 不证明业务目标完成，更不证明后台任务结束。管道状态遵循当前 Shell／`pipefail` 语义，不能悄悄修改选项；脚本、函数和嵌套解释器的内部命令不是逐条完整观察对象。

命令关联不能仅依赖命令文本相同；同名命令、重试、旧事件和手动命令要能区分。事件中的 nonce／序号是关联手段，不是认证凭据。输出与结束事件的边界、完整顶层命令的采集及多行／heredoc 处理需通过真实 PTY 验证，不能以按键流或 `DEBUG` 单次片段猜造完整命令。

## 5. 普通、危险与未知风险

风险分类在本机宿主完成；模型可以说明意图，不能给自己标记“已批准”。本版需要明确可支持的普通操作、上下文和语法边界，而非继续把所有不在短名单中的命令都当危险，也不能通过扩大关键词名单假装覆盖任意 Shell。

删除／覆盖重要数据、权限或账号变更、提权、服务中断、数据外传等已识别危险操作仍逐项批准。复杂组合、重定向、脚本／解释器、动态展开、别名或函数导致作用无法确定时标为未知风险；不因命令名称看似只读、模型说安全或未命中危险词就自动执行。如何兼顾常用别名与正确分类需实测和评审，不能为方便禁用用户别名。

授权始终在本机，绑定确切动作、目标、会话及相关快照，只能使用一次。Shell 事件、远端输出、旧日志、模型文字均不能批准危险命令或提升权限。远端能伪造 lifecycle 元数据，因而这只是受约束的合作式就绪证据，不是可信审计或安全沙箱；本机授权边界不能依赖远端自行声称“安全”。

## 6. 失去关联、交互与人工输入

| 情况 | 后续行为 |
| --- | --- |
| begin／end 缺失、重复、乱序、超限，hooks 被覆盖 | 标记未知并暂停后续自动派发；不靠静默超时推定完成 |
| `exec`、`exit`、Shell 崩溃或连接断开 | 不保证收到 end；旧动作、就绪和批准失效，不自动重发 |
| 编辑器、REPL、密码提示等交互过程 | 不当作普通命令已完成，不向未知程序继续输入；转人工或另行明确支持的交互流程 |
| 前台返回但后台工作仍运行 | 如实报告前台返回，不能宣称后台结束或据此保证后续动作无冲突 |
| 手动输入与 AI 同时发生，关联不能确定 | 说明结果不确定，停止依赖该关联继续执行；不猜造来源或完成状态 |

用户继续自行避免手动与 AI 输入冲突。本版不增加自动手动接管锁，不依据键盘活动自动暂停／恢复，不宣称能够仲裁或撤回已发送字符。现有 AI 动作所有权和字节发送检查仍保留；用户并发输入可能改变前台程序或环境，检测与关联没有完备保证。已观察到的代次或上下文变化必须使相关旧动作失效。

“停止 AI”阻止后续自动派发，不等于 Ctrl+C 或远端回滚。恢复先核对当前目标、Shell 和实际状态；必要时允许一次恢复确认，但不得把确认解释成上一命令成功，或重发结果未知的命令。正常支持路径不退化成每条命令人工就绪。

## 7. 执行状态与可选日志分离

同一当前 Shell 生命周期来源可提供两个独立消费者：执行状态机只保留推进所需的短期状态；日志服务仅在用户开启记录后保存所需记录。日志默认关闭、暂停、容量满或写盘失败，不应关闭已正常工作的执行状态追踪，也不应自动启用日志。

日志故障只影响记录，明确显示缺口；集成本身故障则使依赖该证据的自动执行暂停。关闭日志不卸载仍被执行状态使用的 hooks；停用自动执行也不擅自关闭用户仍需要的日志。消费者的启停和共享采集生命周期须明确管理。

已有 SQLite 历史、导出的 JSON／CSV 永远不能用于恢复执行或批准。远端协议元数据继续从模型普通观察流剔除；执行可用不表示全部终端输出都可发送模型。日志仍需明确同意本地明文风险，不补录暂停期间数据，不保存密码提示输入或默认保存终端输出正文。

## 8. 实现前评审及验收门槛

- 确定首批 Bash 版本及 hook 组合；验证既有 alias／function／prompt／hooks、退出码、异常退出与移除恢复，不能仅以干净 Shell 成功判定支持。
- 确定首次就绪识别、命令完成与 Shell 就绪的独立证据、协议版本、Shell 实例／动作关联、事件边界、容量／超时及迟到事件规则；失败默认未知。
- 评审普通／危险／未知分类及动态语法边界；覆盖绕过、别名重定义、复合命令和过期授权，保留已知限制。
- 真实 OpenSSH PTY 验证连续普通命令无需逐条确认、危险命令仍需批准，以及交互／丢事件／重连不自动继续；不同日志开关与故障组合分别验证。

上述全部为待执行验证。当前未承诺任意 Shell、任意提示符插件或任意命令的可靠自动完成判定，具体测试见 [05 — 迁移与测试计划](05-migration-and-test-plan.md)。
