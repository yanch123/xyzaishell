# 03 — 架构与安全边界

状态：工程提案，待评审，尚未实施；本期优先复用现有模块，不重写 SSH、模型执行或日志系统。

## 1. 职责划分

| 边界 | 拟承担职责 | 不承担的职责 |
| --- | --- | --- |
| 桌面 UI | 设置草稿、统一连接管理、凭据输入、消息与必要确认 | 读取已存秘密、决定安全回退、直接写配置 |
| Tauri 宿主／应用服务 | 校验请求、协调保存与连接、产生脱敏状态 | 把设置或凭据接口注册成模型工具 |
| 模型配置管理 | 安全摘要、Key 更新意图、受限文件保存、快照与接收方确认 | 向 UI 回传旧 Key、自动发送草稿或聊天上下文 |
| 档案／凭据存储 | 档案元数据、逐档案保管策略、平台凭据与迁移 | 明文保存 SSH 秘密、替用户降低保护级别 |
| SSH／AI／日志模块 | 延续原有会话、执行授权、观察和日志边界 | 多 SSH、隐藏 exec、SFTP、批准重放 |

主要落点为现有 `SettingsDialog`、`ConnectionDialog`、`ProfileDialog` 及对应 bridge、Tauri 命令、`model.rs`、`host_storage.rs` 和 `storage/profiles.rs`；具体拆分随实现评审确定，不预先承诺新的大型服务层。

## 2. 配置保存

模型设置仍写入本次进程选择的 `model.toml`。UI 只改负责的字段，后端读取并保留合法高级字段；不得用只有三个字段的新文件覆盖已有超时、能力或传输配置。未知 schema／损坏文件停止写入并给出修复入口。环境变量覆盖的目标错误时不静默换默认路径。

保存使用已有私有目录及文件校验、稳定跨进程锁、期望版本比较、受限同目录临时文件和平台安全替换。外部编辑器不一定遵守锁，因此还要核对文件内容版本；提交失败与提交结果未知分开。备份也含秘密，必须同等保护，不能无限保留或进入 Git。

持久化状态、当前可发送配置与测试草稿分开管理。已启动请求固定快照；保存／重载不改变它，也不复用过期接收方授权。外部错误配置不能被描述成已生效。模型 Key 继续使用现有受限 TOML，非系统保险库；本版不新增模型 Key 存储体系。

## 3. 逐档案策略

建议只有两种持久意图：`ask_on_connect`（不保存秘密，按需询问）与 `system_secure`（明确选择系统保护保存）；名称尚待接口评审。临时凭据是一次连接尝试的输入，不是另一个全局存储模式。后端能力状态与每档案策略分离，某提供者故障不会重写所有档案。

Windows 继续使用 DPAPI CurrentUser；Linux 继续使用 Secret Service。密文／引用保留平台与档案用途绑定。无凭据的私钥档案不等于必须询问口令，只有加密私钥实际需要时询问。临时输入不落盘，提交后清除 UI 副本，在认证结束、失败或取消后释放后端短期值，不宣称能消除所有内存副本。

凭据写入与档案文件不是一个原子事务：写新安全条目、提交新引用、核对成功后再清理旧条目；不确定时先重读，不先删除旧条目。取消记住、删除档案、认证身份变更和恢复保存都必须只影响目标档案。清理仅针对可确认由本应用拥有且无引用的条目，不扫描或删除用户其他凭据。

## 4. 统一反馈与权限

消息是状态的安全投影，不是权限源。按操作 ID、修订和 SSH 会话代次去重及忽略迟到结果；用户切换表单后，旧响应不能覆盖新输入。近期消息有界且默认进程内保留，清空消息不清除实际错误或未决决定。

配置、密码输入和平台凭据操作只开放给可信本机界面。模型不可调用它们；API Key、SSH 密码／私钥口令不进入 prompt、工具结果、普通事件、URL、错误正文、日志或导出。Key 只在用户确认的目标上作为认证使用，不跟随重定向外传。详细帮助不披露秘密；终端原始回显和未知变形秘密的剩余风险继续明确说明。
