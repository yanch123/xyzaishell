# 02 — 桌面交互设计

状态：交互提案，待评审，尚未实施。详细布局、控件文案和快捷键不视为已冻结。

## 1. 主窗口

主窗口建议从上到下为：菜单栏、常用工具栏、工作区、可展开消息面板、紧凑状态栏。工作区保留左终端、右 AI；已保存连接作为左侧可收起的窄列表，不长期挤占终端宽度。小窗口可通过“连接管理”入口打开同一列表和编辑器。

建议菜单：

- 连接：新建连接、已保存连接、重新连接、断开。
- 查看：连接列表、消息面板、终端日志。
- 工具：设置。
- 帮助：使用说明、配置与凭据帮助、关于。

工具栏只放新建连接、连接／断开、连接管理、设置、消息入口等高频动作；不为尚未实现的多会话或文件传输显示占位按钮。菜单、工具栏和列表调用同一操作路径，不各自维护连接状态。快捷键应检查系统冲突及终端键盘语义后确定，不截获终端常用组合键。

状态栏概括：当前 SSH 目标与状态、模型是否可用／待确认、消息数量或待决定事项。模型未配置不影响手动 SSH；某档案凭据无法读取不代表整个应用不可用。

## 2. 独立设置入口

“设置”使用专用设置界面，与聊天输入和 SSH 连接表单分开。第一阶段建议采用单一可复用的设置窗口式面板，不要求新增第二个 OS 进程或独立原生窗口；原生窗口形态在评审时决定。

设置分类导航建议为“模型／通用／历史记录”。模型页承载本节配置；通用页整理现有应用与能力说明，不凭空新增主题、代理或启动选项；历史记录页复用现有历史保存、查看和恢复控制，保留明文保存同意及不恢复执行的边界。

### 2.1 默认展示

- Base URL：API 根地址，短提示说明不要填完整 `/chat/completions` 路径。
- API Key：空白的密码输入框；已有 Key 时显示“已配置，留空保持不变”，不把原值回填到前端。
- 模型名：精确模型标识。
- 操作：保存、测试连接、取消／关闭。
- 当前状态：已保存／有未保存修改、正在保存／测试、测试结果及目标摘要。

输入框没有修改时表示保留，而非清除。替换 Key 后可取消替换；清除通过独立明确动作，不用“删掉星号”表达。清除后模型变为未配置完整并禁用发送，不能保留可继续发送的旧授权；具体文件表示需在接口评审时统一。

### 2.2 保存

1. 本地校验字段；错误直接显示在字段附近。
2. 后端按当前文件版本保存，保留 UI 未编辑的合法高级字段；返回安全摘要和新的修订。
3. 成功后显示“模型设置已保存”；需要接收方确认时同时显示“发送前需确认接收方”。保存不发送模型请求。
4. 文件被其他实例或编辑器改动时，提示重新读取和核对；不静默覆盖。不确定结果要求重读，不能重复点击再次写入。

正在运行的模型请求继续使用启动时快照；新设置用于之后的请求。用户需要立即换服务时先明确停止当前 AI 请求。停止 AI 不保证已发到远端的程序停止。

### 2.3 测试连接

测试按钮针对当前编辑草稿，并明确标注“测试当前填写内容，不自动保存”。测试前显示规范化目标、模型和“仅发送最小测试文本，可能产生服务商费用”。已确认且未改变的同一草稿不重复弹出普通说明；目标或相关配置变化使旧确认／测试结果失效。

测试草稿只在后端短期使用；不把旧 Key 读回前端。测试不携带当前聊天或终端上下文，不执行任何 SSH 命令，不把结果计为工具调用兼容性通过。测试完成在设置页显示摘要，同时进入底部消息面板；提供取消，不因超时自动重复请求。

测试通过但未保存时明确提示“测试通过，设置尚未保存”。保存后若实际内容不同，不能沿用该测试通过标记。初期测试范围建议保持现有流式聊天验证，不额外扩大为完整工具协议认证。

### 2.4 更换目标与 Key

- 修改模型名但不换目标：允许保留旧 Key；重新核对配置并使旧测试结果失效。
- 修改 Base URL 得到不同的规范化请求目标：清除旧接收方确认；不默认把旧 Key 用到新地址。
- 用户可填写新 Key，或明确选择“将已有 Key 用于这个新目标”；后一选择显示新目标，再在发送测试／聊天前取得对应的数据发送确认。
- 不以“两个域名属于同一品牌”推定等价；API 重定向不能把认证带到另一目标。

### 2.5 高级区与帮助

高级区默认折叠：当前 TOML 路径、是否受 `XYZAI_MODEL_CONFIG` 覆盖、重新加载，以及当前已有高级字段的说明。环境变量仍指定绝对文件路径，修改后重启选择新路径；不新增一个会修改系统环境变量的按钮。

文件损坏、不可写或路径不可用时，展开相关错误和修复说明；不悄悄改写默认路径。重新加载前若有未保存修改，询问保存、放弃或取消。帮助说明 API Key 的现有明文 TOML 风险、私有目录要求，以及不要将配置提交到 Git 或同步／共享目录；普通用户不必每次阅读全部机制才能操作。

## 3. 统一连接管理

### 3.1 列表与操作

列表显示名称、`用户@主机:端口`、认证方式、凭据策略摘要及当前连接标记；不显示密码或私钥口令。凭据状态应区分“未保存”“已保存”“暂不可用”，不能只用一个锁图标暗示已经能登录。

- 单击选中；双击发起该已保存版本的连接。
- 右键提供连接、编辑、重命名、删除；这些操作也有可见按钮或菜单供键盘使用。
- 重命名只改标签，不要求重填秘密、不改 ID。
- 删除确认说明目标档案和凭据处理范围；不删除用户私钥文件，不删除 known_hosts、聊天或 Shell 日志，不自动断开现有会话。具体安全存储条目清理按后端结果显示。
- 重复双击只产生一个连接尝试；列表刷新后不把同名档案误认为原档案。

### 3.2 新建与编辑表单

常用字段放在同一页：名称、主机、端口（默认 22）、用户名、认证方式、密码或私钥路径／口令。为临时连接填写名称是可选的；保存档案时要求名称。

秘密区提供“记住密码”或“记住私钥口令”，新建时默认不选。旁边简短说明“仅保存在本机，使用系统保护；本机账号或系统被控制时仍有风险”，详细机制放帮助。编辑已有档案显示“已保存，未修改时保留”，既不回填真实秘密，也不因空输入框清除它。

按钮语义：

| 按钮 | 保存档案 | 保存秘密 | 发起连接 |
| --- | --- | --- | --- |
| 仅连接 | 否 | 否 | 使用当前草稿和本次凭据 |
| 保存 | 是 | 仅明确选择且后端成功时 | 否 |
| 保存并连接 | 先保存 | 仅明确选择且后端成功时 | 只对已核对的保存结果继续 |

“仅连接”不改变原档案或其记住密码选择，即使从编辑页进入也如此，按钮附近要显示这一点。若选择记住密码，应使用保存类按钮，不出现“临时连接却悄悄保存”的组合。

保存并连接分别展示阶段：“正在保存”→“已保存，正在连接”→“已连接”或“已保存，连接失败”。保存失败／冲突／结果未知时不自动继续连接；可在核对后明确选择临时连接。网络连接失败不会撤销已成功保存的档案。

### 3.3 缺失或不可用的凭据

1. 用户发起连接，先读取所选档案的最新版本和凭据状态。
2. 可读取的持久凭据在后端直接用于对应认证；前端只得到状态。
3. 缺少密码时，在当前连接流程中显示专用密码输入步骤，保留服务器信息，不要求返回档案编辑器重新建立资料。
4. 私钥文件未加密时不询问口令；需要口令时再询问。私钥缺失／权限不符显示针对路径的错误，不把所有问题都说成密码错误。
5. 输入默认仅本次认证；用户可明确选择为该档案记住。后端不可用时提供“只用本次输入连接”及解锁／恢复帮助，不自动改变原来的保管策略。
6. 用户取消后不连接、不保存输入；认证失败后清除输入，允许重新填写。不自动循环重试密码，也不误报已保存密码就是已验证密码。

### 3.4 改动、切换和关闭

编辑标签等非认证信息时保留凭据。修改目标主机、端口、用户名、认证方式或私钥路径时需重新核对认证绑定；不能把旧密码／口令无提示地用于新身份或新密钥。具体复用选择在接口评审中明确，默认采用重新输入或明确确认复用。

已有 SSH 会话时连接另一档案，先提示当前目标和切换影响；有 AI 工作时先处理停止／未决操作，再显式断开并新建。失败后保留准确的实际连接状态，不宣称退回原会话成功。手动“重新连接”沿用目标资料并重新核对档案版本，按需询问凭据，产生新会话代次；不并行建立第二条 SSH、不自动重试、不恢复旧批准或重放命令。

编辑后关闭、切换档案或重新加载时，提供保存、放弃、取消。密码输入属于未提交修改，取消必须清除。保存请求已送出后关闭界面不能保证写入被撤销；需等结果或回来重读状态。重复打开设置／连接管理复用现有实例，不创建叠加弹窗。

## 4. 底部消息面板

默认收起为一行状态，出现重要错误或待决定事项时显著提示并允许展开。面板不抢走终端输入焦点；需要决定的事项保持可发现，不能被普通消息刷走。

每条消息建议包含时间、来源（连接／模型／配置／日志）、级别、简短结果、可展开详情、错误码和安全的恢复操作。按一次操作聚合更新，避免把“开始、进行中、成功”刷成大量重复行。近期消息有上限，默认只在当前进程保留；历史持久化和导出不作为本期新增能力。

- 普通结果：保存成功、连接建立、模型测试结果、日志导出路径。
- 故障：连接失败、配置冲突、安全存储锁定、保存结果未知；给出准确影响和下一步。
- 帮助：解释当前配置和凭据策略，由用户主动展开。
- 待决定：面板提供回到原决策入口的按钮，不直接把“关闭消息”“全部已读”转换为批准。

表单仍保留必要的字段校验，决策仍留在对应上下文。消息面板不是终端输出、Shell 命令日志或聊天历史的副本，不自动复制命令正文、API 响应或秘密。详细信息只增加安全定位信息，不以“详细模式”绕过脱敏。

## 5. 保留明确决定的场景

首次／变化的主机密钥、风险命令及未知终端状态、模型接收方／数据范围、已有连接切换、丢弃编辑、删除档案或移除已保存凭据，以及现有明文历史／Shell 日志启用同意，均不能被“减少弹窗”取消。

普通提示尽量内联；确需决定时展示明确对象、影响和取消路径。关闭弹窗、超时、消息已读、测试通过均不代表同意。恢复旧聊天只恢复文本，不恢复执行和历史批准。
