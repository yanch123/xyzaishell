# 06 — 分阶段交付计划

状态：实施计划草案。本轮只完成 D0 文档，后续代码、版本和发布尚未授权。

| 阶段 | 范围 | 离开本阶段所需结果 |
| --- | --- | --- |
| D0：设计整理 | 本目录索引、需求、交互、架构、契约、迁移测试计划 | 内容与范围核对、相对链接及 docs-only 检查；用户评审 |
| D1：模型设置 | 独立编辑界面、原配置保存、草稿测试、Key 与接收方处理 | T1–T4；高级字段不丢失，秘密不回填 |
| D2：连接与档案 | 统一入口、保存并连接、按需认证、逐档案策略及迁移 | T5–T9；旧 session_only 可恢复，平台故障不影响资料保存 |
| D3：桌面交互 | 菜单、工具栏、列表操作、消息与帮助入口 | T10–T12；不抢终端焦点，必要决定未被弱化 |
| D4：跨平台验收 | 合成数据集成、原生安装、升级和回归 | 精确提交的证据矩阵；失败与未测项明确 |
| D5：发布评审 | 版本号、发布说明、安装包和发布检查 | 另行获得发布授权，并完成最终候选验证 |

每阶段可以在 dev 上采用小范围提交，但不能用阶段计划推定已获实施或发布授权。D2 的迁移格式应先于对旧数据的实际写入完成评审；D3 可先做非破坏性结构，但不能用 UI 先行掩盖底层凭据限制。

## 1. 设计评审重点

1. 设置采用单一窗口式面板还是独立原生窗口；连接列表默认展开状态与工具栏密度。
2. 测试当前草稿但不自动保存的文案；清除 Key 的持久表示及未配置状态。
3. 逐档案策略和连接 schema；旧 session_only、不可用安全存储、身份变更时的恢复／复用操作。
4. 消息面板与必要确认的边界；删除档案和移除凭据的准确影响说明。

这些是工程落地选择，不能反过来改变已确认的目标：软件内配置模型、统一连接管理、可选记住密码、资料与秘密分离、左终端右 AI、一个 SSH／进程、无 SFTP。

## 2. 发布门槛

实现完成不等于已发布。后续只有在用户另行确认后才更新应用版本、修改 release intent、构建候选或创建标签／Release；不修改历史发布内容。使用同一精确候选提交的构建、测试和安装验收结果，不以旧提交的绿灯替代。发布说明需区分新能力、数据迁移、明文模型 Key 风险及未覆盖平台范围。

本轮交付说明只能声称“v0.1.2 编号设计文档已整理”，不能声称“v0.1.2 设置／连接功能已经可用”。
