## 1. 设计评审重点

1. 非模态设置／日志的具体窗口实现、新进程启动与安全资料传递、连接列表密度。
2. 保存与保存并测试的分阶段结果；清除 Key 的持久表示及未配置状态。
3. 逐档案策略和连接 schema；旧 session_only、不可用安全存储、身份变更时的恢复／复用操作。
4. AI 来源与日志范围迁移，旧数据缺失关联的处理，删除档案和移除凭据的准确影响。
5. Bash 兼容矩阵、保留原 hooks 的安装／恢复、前台完成与真正就绪的独立证据，以及普通／危险／未知分类。D4 不能以删掉确认按钮代替后端状态与策略设计。

这些是工程落地选择，不能反过来改变已确认的目标：软件内配置模型、统一连接管理、可选记住密码、资料与秘密分离、左终端右 AI、一个 SSH／进程、多进程独立窗口、无 SFTP；当前 Shell 临时 hooks、普通命令正常路径自动执行、危险授权和未知暂停。

## 2. 发布门槛

实现完成不等于已发布。后续只有在用户另行确认后才更新应用版本、修改 release intent、构建候选或创建标签／Release；不修改历史发布内容。使用同一精确候选提交的构建、测试和安装验收结果，不以旧提交的绿灯替代。发布说明需区分新能力、数据迁移、明文模型 Key 风险及未覆盖平台范围。

本轮交付说明只能声称“v0.1.2 编号设计文档已整理”，不能声称“v0.1.2 设置／连接功能已经可用”。
