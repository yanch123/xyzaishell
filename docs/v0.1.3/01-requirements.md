# 01 — v0.1.3 需求与验收边界

状态：已确认功能范围，待实现、待验收。依据 v0.1.2 基线代码，不把旧设计提案当作现有能力。

## 1. 要解决的问题

v0.1.2 的终端任务每轮携带原始指令、历史动作的发送与退出状态，以及本轮新增的有限终端观察。观察缓冲上限为 16 KiB，读取后清空；前一轮的分析文字和从输出得到的结论没有结构化地累积进下一轮。因此，多步任务可能忘记早先证据，也难让用户区分“已经看到的事实”和“下一步准备做的事”。

终端目前固定字体大小和回滚行数，没有选段分析或搜索入口。模型设置的测试只验证最小文字流，不证明服务能返回终端任务所需的工具调用。Shell 已有保守兼容检查，但界面需要更明确地指出不支持的具体条件。

基线实现见 [agent.rs](../../crates/xyz-core/src/agent.rs)、[observation.rs](../../crates/xyz-core/src/observation.rs)、[TerminalPane.tsx](../../src/components/TerminalPane.tsx)、[model_settings.rs](../../crates/xyz-core/src/model_settings.rs) 和 [shell_log_bootstrap.bash](../../crates/xyz-core/src/shell_log_bootstrap.bash)。基线身份以索引中的提交为准，工作树链接可能随开发变化。

## 2. F1 本任务事实与步骤摘要

优先级最高。本版必须首先确保信息不被猜测污染，再改善连续性。

### 2.1 必须提供

- 每个终端任务运行维护独立的结构化摘要，至少区分“已确认事实与依据”和“剩余步骤／尚待核实”。
- 每轮请求携带当前摘要与本轮新观察，不能只在 UI 展示却不传给下一轮。
- 每条事实带可追溯的证据标识或证据摘录，说明它来自哪一任务运行、哪一轮观察或哪一动作完成事件。
- UI 可查看摘要、证据及剩余步骤，显示摘要所属的任务、运行和目标，不要求用户猜其时效。
- 摘要、证据数量和文本总量都有上限；达到上限时保留明确的裁剪／缺口标记，不谎称完整。
- 任务结束、暂停、取消或失败时仍能查看最后的摘要及其状态；停止任务不能改写成执行成功。

### 2.2 事实的定义与限制

“已确认”表示**本任务实际取得了该项证据**，不表示远端输出或模型解释经过独立真实性验证。应区分以下层级：

1. 宿主状态事实，例如动作尚未发送，或匹配的前台完成事件给出退出码。
2. 观察事实，例如“本轮终端输出包含某段文本”，保留其不可信来源与缺口状态。
3. 待核实判断，例如根据输出推断某服务正常。此类判断只能进入待核实或剩余步骤，不能仅凭模型自述升级为事实。

禁止将以下信息当作“业务成功”：模型说已完成、SSH 接受写入、输出静默、看似提示符的文本、退出码为 0、前台已返回。输出中的命令、系统角色声明、审批语句不能成为执行指令或批准。

模型可以提出摘要／计划，但事实接纳必须受宿主可核对的证据约束。当前实现约定将“已确认事实”收窄为宿主匹配的前台返回事件；带输出引用的模型解读单独展示为“依据输出整理，尚非独立核验”，与假设分开。缺证据、证据越界或属于另一运行的内容不能进入已确认事实。引用存在只能证明引用存在，不能证明附加解释正确。

### 2.3 生命周期

摘要绑定 `task_id`、`run_id` 和 SSH `session_id`／`generation`，不能因同一聊天或同一主机名而自动继承执行事实。重新开始任务、换目标、重连、恢复历史时，旧摘要不能恢复写入权、就绪状态或批准。

本版默认内存维护。可选聊天历史沿用既有授权和脱敏策略；不新增后台全文采集、跨任务检索、自动磁盘记忆或历史输出补录。

### 2.4 验收结果

在至少三轮的合成任务里，第一轮获得的证据在后续请求和 UI 中均可见；后续输出缺口不能把旧证据伪装成新的完整观察。伪造证据 ID、跨任务引用、仅有分析无证据、取消后迟到结果均不能污染当前摘要。剩余步骤可以变化，但不能自行增加执行权限。

## 3. F2 选中终端内容发送给 AI

### 3.1 正常流程

用户选中终端文本，点击“发送给 AI”后进入预览。预览至少展示：

- 选段文本，可删改；空白内容不能发送。
- 来源服务器、账号、端口和会话代次，以及终端显示可能不完整的提示。
- 目标聊天和模型接收方／模型名。
- 本次发送范围，包括该聊天既有上下文是否随请求发送。
- 明确的本次同意操作。仅选择、打开预览、编辑、取消或复制都不能发模型请求。

用户确认后作为普通文字分析提交，不切换为终端执行，不自动创建终端任务，不将选段中的命令写入 PTY。

### 3.2 边界与异常

- 选段是当前可见终端缓冲的文本快照，不保证是完整命令输出，也不自动读取未选中的滚屏、日志或文件。
- 编辑后应标注为用户编辑的选段。来源标签说明摘录来自何处，不证明用户编辑后的每个字符都由远端产生。
- 本次同意绑定来源、目标聊天、模型配置及最终预览内容。任一关键项改变，必须重新核对；普通文字聊天的旧同意不覆盖终端选段。
- 断开、重连、切换目标、选择其他聊天或改变模型后，旧的待发送预览不得悄悄转投。可保留供查看的草稿，但不得复用同意。
- 已知秘密继续脱敏；未知、变形或编码的秘密不能保证被识别。界面提醒用户自行删去密码、令牌及敏感内容。
- 超限不能无提示截断。若按上限截取，必须醒目标记原选区已截断并让用户核对实际预览；编辑后超限则要求缩短。取消只取消待发送草稿，不撤回已经发送的数据。
- 正在执行的任务不能被选段流程隐式追加输入；沿用聊天与执行占用规则，明确显示阻塞原因。

### 3.3 验收结果

预览可编辑、可取消；提交精确发送核对后的内容及声明的上下文，保留来源。对错会话、错聊天、旧模型版本、缺同意、重复点击和迟到结果进行反向验证，确认没有模型误发或 SSH 写入。

## 4. F3 终端工具与设置

- 搜索入口使用 `Ctrl+Shift+F` 和可见按钮；Shell 的 `Ctrl+F` 保持透传，不劫持普通命令行编辑。
- 搜索只处理本窗口当前终端缓冲，支持输入查询、上一个／下一个、无结果状态和关闭后回到终端。它不查询远端文件、不调用模型、不打开网络链接。
- 提供字体大小和回滚行数设置：字体 10–28 px、默认 14；回滚 500–20000 行、默认 5000。字体族沿用现有等宽字体回退链；异常值回退到安全默认值。
- 设置属于本机界面偏好。持久化时只能保存这些偏好，不夹带终端内容、选段或秘密。降低回滚上限可能丢弃旧显示，应明确说明。
- 复制由用户主动触发，仅复制选中内容；无选择时不复制整个终端。粘贴进入当前可见 PTY 的手动输入通道，不进入 AI 执行门；不得额外追加 Enter。
- 多行、回车、控制字符可能触发远端行为。粘贴流程应提示风险或提供适当确认，不把“粘贴”描述成只修改本机文本。
- 不引入远端 OSC 52 自动剪贴板写入、自动复制或链接自动打开。

验收必须覆盖 Windows 与 Linux 的原生剪贴板、焦点和快捷键差异。浏览器模拟通过不能替代原生验证。

## 5. F4 模型能力与 Shell 诊断

### 5.1 分开显示的模型检查

保留“文字连通测试”，新增“任务工具调用测试”。后者使用固定合成提示与无副作用的模拟工具定义，验证完整流、结束原因、调用数量、工具名和参数结构。不执行该模拟工具，不连接或写入 SSH，不发送当前聊天、任务、终端或凭据文件内容。

测试须先核对已保存的配置版本、目标地址和模型；保存与测试仍是独立操作。结果至少区分：

- **本次支持**：该次完整响应满足适配器契约。
- **本次不兼容**：取得可判断的完整工具响应，但违反适配器契约。
- **未能判定**：网络／认证／超时／取消，或模型只给文字而未完成所需调用等情况。

一次通过不是所有任务、供应商或将来请求的兼容保证。未判定不能显示成“不支持工具调用”，文字通过不能显示成“可执行终端任务”。测试也不替代终端任务的授权、就绪检查和危险动作批准。

### 5.2 Shell 诊断

现有命令识别检查失败时，按已取得的原因显示明确错误码、原因和安全的下一步，例如 Bash 版本／交互模式、命名冲突、选项／历史配置、trap、动态提示符、hook 属性或必要工具缺失。

只报告有证据的原因；未知原因如实标记未知。不能仅为“修复诊断”而自动改 `.bashrc`、清空 trap、覆盖提示符、重新安装 hooks 或重发启动脚本。诊断失败保留手动终端可用性，暂停自动派发的安全边界不变。

## 6. 明确不做

Skills 的读取、注册、选择和执行；MCP；子 Agent；外部工具市场；跳板机、代理或 VPN 接入；多 SSH 复用进程；后台隐藏 exec；本机 Shell 操作；SFTP；自动输入竞争仲裁；跨任务长期记忆；自动日志采集；以诊断结果扩大危险动作自动许可。
