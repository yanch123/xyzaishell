## 1. 本版只做四项

1. **优先：本任务的已确认事实、证据与剩余步骤。** 结构化摘要随每轮模型请求携带，并在任务界面可查看；猜测不能作为事实保存。
2. **选择终端内容发给 AI。** 先显示可编辑预览，核对终端来源、模型接收方和本次发送范围，再作为文字分析发送；不会因此开始执行命令。
3. **终端日常操作。** `Ctrl+Shift+F` 搜索、字体与回滚设置、明确的复制粘贴入口；保留 Shell 的 `Ctrl+F`。
4. **模型工具调用与 Shell 诊断。** 将文字连通测试与工具调用能力测试分开；用固定合成数据检验调用格式，不执行工具、不写 SSH。Shell 不支持时给出可定位的原因。

不做 Skills，也不新增 MCP、子 Agent、跳板机、代理或 VPN 集成。其余安全边界沿用 v0.1.2。

## 3. 与 v0.1.2 的关系

现有终端 Agent 已有“观察 → 模型提议 → 风险检查 → 同一可见 PTY 执行 → 前台返回与独立就绪证据 → 下一轮”的受限循环，本版在此基础上补齐上下文连续性和可诊断性，不重写执行体系。

- 一进程一条 SSH 会话、一个可见 PTY；多窗口仍是独立进程。
- 同一 PTY 同时仅一个 AI 任务持有写入权；用户仍自行避免手动输入与 AI 输入竞争。
- 危险动作仍要核对原卡片并单次批准；未知状态不盲目重发。
- 文字聊天、选段分析与终端执行分别保留明确入口和授权边界。
- 前台返回、退出码、模型判断和业务完成不是同一事实。
- 操作日志和聊天历史不被默认开启，任务摘要不引入跨任务记忆库。
- 目标平台继续为 Windows x64 与 Linux x64；安装和原生验收按实际证据说明，不扩大到 macOS、ARM 或所有 Linux 发行版。

v0.1、v0.1.1、v0.1.2 文档原样保留。仓库主 `README.md` 继续面向使用者，不放需求设计、开发流水或未经验证的完成宣告。
