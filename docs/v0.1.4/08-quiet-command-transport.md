# 08 — 同一 PTY 的安静命令传输

## 1. 目标与交互

AI 命令仍在当前可见 SSH PTY、同一个父 Bash 中执行。短启动行替代原先数万字符的十六进制封装；接收成功后只打印一次 `[AI] 原始命令`。启动行本身仍可能可见，但长度有界，不再随原始命令成倍增长。

不删除整个 Begin 之前的输出，不擦除终端，不隐藏后台程序输出，也不需要用户启用额外配置。原始终端输出照常展示。

## 2. 一次批准、两个阶段

宿主生成不可变的原始命令、短启动行和接收帧；批准摘要以独立域和长度前缀绑定两个精确传输部分。第二次写入只是同一许可的一次性延续，模型不能单独调用。

`Ready → AwaitingReceiver → Receiving → AwaitingBegin → Running → AwaitingReady → Ready`

接收器准备好终端模式后发送 v3：

`M;sequence;session;generation;action;digest`

外层仍包含 Shell nonce。宿主核对所有身份、当前所有权、取消状态、批准期限和接收期限；消费该握手后只发送一次帧。重复、过期、异会话或乱序 M 均不能授权写入。A/Z 继续准确关联原文开始和退出状态，R 仍是独立的提示符完整性检查。写入回执不代表命令成功。

## 3. 任意后缀也不可执行的帧

解码后的记录：

`v1|nonce|session|generation|action|sequence|sha256|byte_length|original_command`

每个字节编码为八个字符：`#` 表示 1，ASCII 空格表示 0；帧另加开头 `#` 和结尾换行。任意延迟或被截断的后缀都只含空格和注释字符，在启用 `interactive_comments` 的 Bash 提示符中不会成为命令。普通十六进制/base64 不具有这个性质。

原始 UTF-8 命令上限仍为 8192 字节，内部接收帧独立限制为 128 KiB。接收器验证字符、长度、身份和 SHA-256；只用有界算术和 printf 解码，解码阶段不使用 eval。新增显式运行能力要求为 `stty` 和 `sha256sum`，缺失时保留手动终端并停止自动执行。

## 4. 终端模式与顶层执行

接收器保存完整 `stty -g` 状态，在发送 M 之前设置 `-echo -icanon noflsh min 1 time 0`。先关闭规范行模式，避免约 4096 字节的终端行上限截断最大帧；不能先发 M 再依赖 read 关闭回显。

接收期间临时启用 `noflsh`，避免分开发送部分帧与 Ctrl-C 时，终端驱动刷新输入/输出与 Bash 的中断清理发生竞争。原生 Bash 5.2 的真实 PTY 已复现这种竞争会让提示符清理延迟到下一次输入；不能靠额外输入或延长等待掩盖。中断后的提示符清理先用 `read -t 0` 检查已有输入，再有界消费当前排队的接收字节，避免残留注释吞掉下一条手动命令；不等待后续帧，最多检查 128 KiB。读取结束与模式恢复之间仍可能排入字节，因此取消路径会在恢复后再做一次同样的即时检查；每次单字节读取都会还原其进入时的终端模式。未来仍在途的后缀遵守下述手动输入竞争边界。未消费的帧后缀仍只有空格和注释字符，所有终端设置包括 `noflsh` 都按保存值精确恢复，不改变用户的长期配置。

接收阶段临时安装 INT 处理器，标记取消并明确从接收函数返回 130；保留原始模式快照，由后续提示符清理在 Bash 内建 read 完成回退之后排空当前队列、恢复模式并记录一次失败。不能只在处理器内部恢复，因为 read 自己的回退可能再次覆盖终端设置。

Bash 4.2 使用一次 `read -r -s -t 15 -n 131072`，避免该版本超时读取会丢弃部分输入。现代 Bash 能保留超时前的字节，使用最多 60 次四分之一秒读取并共享一个 15 秒截止时间，避免待处理的 INT 一直推迟到长读取结束；片段不续期，独立次数上限防止时钟回退导致无限等待。两条路径均严格限制总输入 128 KiB；整秒时钟和调度存在粒度，不宣称毫秒级精确截止。准备阶段已拒绝自定义 INT 处理器；恢复函数在成功、失败和提示符清理路径均撤销这一临时处理器，Begin 和原文 eval 之前已回到原来的默认 INT 行为。成功、失败或超时都先恢复精确原模式；中断后的首个提示符钩子恢复尚未恢复的模式。恢复失败不执行原文、不重新就绪。

校验完成后才发 Begin、打印原文。调用者在**顶层**执行 `builtin eval -- "$__xyz_payload"`，立即将 `$?` 交给 End，然后等待独立 Ready。不是函数内或子 Shell 内 eval，因此 cd/export 状态保留。

## 5. 失败与手动控制边界

任何阶段都不重放。启动行已发送后的取消、部分写入、超时、断线或回执不确定，结果保持未知。宿主接收/续写期限短于远端读取期限。无法证明远端已恢复时，可以关闭连接，不能将排队输入交给不确定的接收器，也不自动重连或重发。

用户仍自行控制手动终端，应避免同时输入。在途字节无法撤回；Bash 提示符下的后缀安全，不代表用户中途打开密码提示或编辑器后仍可安全接收这些字节。本版不暗中增加键盘仲裁。

不创建永久远端文件、后台服务或第二条 SSH 通道。

## 6. 验收

Bash 4.2.46、5.1、5.2 均需真实、开启回显的 PTY，并覆盖 OpenSSH：

- 8192 字节原文完整执行，接收帧无回显，原文只显示一次；
- 退出状态、持久 cwd/export、别名和提示符钩子不变；
- 成功、超时、Ctrl-C 后精确恢复终端模式；
- 任意部分帧、延迟后缀不在提示符执行；
- 各阶段取消、重复/异会话 M、许可篡改均不重放；
- 接收前及接收中的后台输出不丢失；
- 错误身份、摘要、长度或编码不能产生 Begin；
- 父 Shell 死亡不伪造 End/Ready。
