# 06 — 通用执行边界与 Bash 兼容

状态：修订设计；实现与验收以 development 记录及精确提交 CI 为准。取代“依赖 PS0／DEBUG 才能执行所有 AI 命令”的假设；当前已提交的初版代码不代表此设计已经完成。

## 1. 为什么区分 AI 执行和手动日志

Bash 4.2 没有现代 PS0 行为。DEBUG 在部分子 Shell、展开或复合语法前不能提供完整的顶层开始事件。不能仅取消版本判断，也不能把第一个后来出现的 DEBUG 当作整段脚本开始。

- AI 动作：客户端知道批准的完整内容，可以使用显式执行边界。
- 手动命令日志：只能根据 Shell 提供的真实证据记录；无法识别时标记缺口，不猜测命令、时间或成功。

两者共享可见终端，但不能因为旧版手动日志较弱就把所有正常 AI 命令都硬拦。

## 2. 同一持久 Shell 的动作封装

在确认当前 Shell 可接收输入后，宿主为一个不可变动作生成完整、单次的执行封装：

1. 校验当前 session、generation、Shell 身份和独立就绪证据。
2. 绑定 action ID、原始命令字节、策略判定和精确授权；生成完整封装后禁止修改。
3. 按 [08 安静命令传输](08-quiet-command-transport.md)，在同一可见 PTY 先发送短启动行；匹配接收握手并重新校验同一不可变许可后，仅一次续写无回显的后缀安全帧。接收器校验原文后显示一次 `[AI] 原始命令`，不过滤后台输出。
4. Shell 在顶层发出该动作开始事件，再解释执行经完整转义、无提前插值的原始命令。
5. 原命令返回后立即保存退出码，发出匹配结束事件。
6. 最终提示符钩子另发就绪事件；结束和就绪都匹配后才允许下一条命令。

实现优先使用**顶层**解释执行，避免函数包装给 local／declare／return 带来的局部作用域变化；也不在隐藏 SSH 通道或另一个一次性 Shell 中执行。cd、export 等状态应留在当前可见 Shell，并通过测试验证。

这不是把模型文本拼进 eval：模型只提交原始命令数据，宿主完成严格字节编码与封装，批准绑定的是原文和实际将发送的不可变封装。编码须覆盖引号、换行、反斜线、Unicode 和边界长度，不允许传输结构被命令内容逃逸。NUL／终端控制字符拒绝。封装被部分发送、失去返回或连接中断时结果未知，不重发。

协议设计需有版本号、session/generation、Shell nonce、action ID、序号、原文摘要；普通输出与控制事件严格分离。远端可修改环境和伪造输出，因此此机制不构成对恶意服务器的安全证明，更不能授予本地审批权限。

## 3. 语法、风险和生命周期分开

- 普通命令、带参数的程序、可解析的管道／顺序列表／重定向：按完整动作原文判定风险，不能仅因出现未知程序名而永久禁止。
- 不能证明低风险的动作：需要核对完整内容后单次授权；授权不是成功保证。
- 替换当前 Shell、退出、修改控制钩子／陷阱、改变输入状态、控制终端本身等：涉及执行协议生命周期，必须有专门动作支持，否则明确需手动处理。
- 后台和持续输出命令：前台返回不等于后台完成，不能宣称任务成功。没有专用任务生命周期时不自动进入下一步交互。
- 交互式编辑器、分页器、密码读取：不把下一条普通命令发送进去。先暂停，用户处理或使用专门的秘密输入流程。

风险不等于语法不支持；危险但能准确表示的动作走批准，无法可靠控制的执行形式才是能力边界。详细判定契约见 04。

## 4. 连接准备与保留状态

新连接使用同一 PTY 的受控非登录交互 Bash，读取 .bashrc，自动安装临时识别，不写服务器启动文件、不安装常驻服务。明确说明它不等同于所有登录 profile 的初始化。

启动脚本阻塞时不向 stdin 粘贴初始化命令。不确定是否启动时不再次启动；只有服务明确拒绝且确认未开始，才允许同通道手动 Shell 回退。

保留受支持的用户别名和提示符钩子，不自动清理用户配置来通过验收。Bash 4.2 的默认忽略 SIGTSTP／SIGTTIN／SIGTTOU 与自定义处理器不同，只有被实际运行验证的精确默认形式可规范化；其他 trap 仍需判断冲突，不能一律忽略。

## 5. 必须验证的版本与行为

用户当前使用 4.2.46(2)-release，但不限制产品只支持这个版本。最低验收矩阵：实际 Bash 4.2.46、5.1、5.2。按能力选择适配器，未测环境不得笼统宣称完全兼容。

每个版本验证：cd/export 保留；简单命令、管道、顺序命令、受控重定向；多行输入的拒绝／零写入；非零退出码；引号／Unicode；Ctrl+C；无输出；启动读取密码；假控制帧；钩子被修改；退出／exec 的拒绝／零写入；部分发送；断线。不能以单元测试代替实际 Shell 和真实 OpenSSH。

2026-10-16 的初步 4.2 DEBUG 原型在真实版本测试中失败，不能宣称已支持。它证明了普通默认 trap 差异和 DEBUG 的边界；新封装路径必须重新验收。

控制原语名称（包括 builtin、eval、printf、trap、history 等）的函数／别名冲突必须检测并拒绝自动准备，不覆盖用户定义；不能假设任意同名调用必然是预期内建命令。

## 实施收敛说明

本版准备仍要求受支持的 history／HISTSIZE 配置，因手动钩子识别信封输入仍依赖历史窗口；不声称支持任意关闭历史的配置。对于没有待派发或活动 AI 动作时发生的已知手动观察缺口，日志保留缺口，宿主只转入等待状态，收到独立且序号匹配的 Ready 后才恢复可执行。钩子篡改、AI 活动中的缺口及结果未知均不能走此恢复路径；不伪造手动 Begin/End，也不把缺口当成功。

最终旧版方案不安装 DEBUG trap：Bash 4.2 的手动变化仅记录提示符观察缺口，不生成虚构的手动命令开始／结束；AI 原文仍按显式封装准确关联。modern exact 仅指受支持的 PS0 记录能力，不是不可篡改审计。IntegrationStatus.manual_tracking 告知日志界面。空行产生的空闲同序号 Ready 仅在无待派发／活动 AI 时刷新就绪 revision，使旧绑定失效，不解决未知 AI 结果。
