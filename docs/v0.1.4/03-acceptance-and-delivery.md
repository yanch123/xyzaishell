# 03 — 验收与交付

所有项目为待执行计划，只有对应精确提交与结果才能记为通过。

## 必测用户路径

1. 无 SSH 时同一输入框问候／解释正常，不显示“终端忙”错误。
2. 首次连接支持环境，自动准备完成；不用手动启用识别，不弹每任务确认。
3. 普通检查命令展示后经真实同一 PTY 执行，匹配结束＋独立就绪后继续；连续追问读取前文与结果。
4. 危险命令未批准零写入；批准仅适用原命令和会话；修改、取消、重连、换服务器后旧批准失效。
5. `.bashrc` 自定义别名／受支持钩子保持；启动脚本读取密码或进入前台程序时零 bootstrap stdin 注入，超时不重发。
6. 不支持 Shell／exec 明确拒绝／启动结果不确定分别处理，不暗中重连或第二通道运行。
7. 统一能力许可在模型／目标变化后失效；文字-only 旧许可不能用于终端。
8. 选区内容只是数据，预览编辑和单次同意不绕过；含命令的选区不能自行触发操作。
9. 多聊天、断线、取消、迟到事件、IPC 结果未知不导致重复提交或双写。
10. 长聊天有界裁剪、已知秘密跨边界处理、模型推测与宿主事实仍区分，达到轮数上限明确停止。

## 平台与交付

前端单元／类型／生产构建；Rust 单元／集成／格式／严格 Clippy；真实 OpenSSH 与 Bash PTY；浏览器宽窄截图；Windows NSIS 和 Linux DEB；三种托管环境安装／重启／重装／卸载及真实 v0.1.3→v0.1.4 升级。锁定公开 v0.1.3 实际资产与摘要，不混用候选 CI 产物。

本机用户桌面、真实外部模型供应商、输入法／剪贴板／Wayland 的验收独立列明，不用模拟测试替代。下载安装包、provenance、源码与校验和必须核对精确提交。

阶段：设计文档 → 自动准备与统一后端 → 统一前端与回归 → 整合验收与用户指南。每阶段提交 dev；本次开发不改写 v0.1.3 标签或 Release。main／新 Release 只在版本验收和发布授权范围内推进，不能提前宣布完成。

## Bash 4.2 兼容门槛

通过官方 GNU 源码及补丁构建实际 4.2.46，固定来源和摘要，运行同一 PTY 生命周期与真实 OpenSSH 验收。AI 动作验证显式封装的管道／列表／重定向与独立完成；手动日志单独验证 4.2 提示符观察缺口（无 DEBUG）、现代 PS0 识别、复合语法缺口、Ctrl+C、既有 trap 拒绝、别名和钩子篡改。拒绝的子 Shell／展开／多行载荷必须零写入。Bash 5.1/5.2 仍必须回归。
