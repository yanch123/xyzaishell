# 02 — 架构与接口约定

状态：初版接口基线；最终代码与验收需复核一致性。通用命令执行的修订以 04、06、07 为准，不能把本文已有初版实现当作全部能力已完成。

## 统一入口

新增宿主入口 `submit_conversation_turn(chatId, text, revision, destination, session)`，结果为带标签的 `chat`（ChatSnapshot）或 `terminal`（TerminalTaskSnapshot）。配置和 session 参数仅为期望值，用于拒绝迟到的旧请求，不能赋予权限；不接受渲染层伪造“已空闲”作为执行证据。宿主读取当前配置、许可范围、连接身份和命令识别状态。

- 当前服务器已就绪且具备对应能力许可：进入支持文字回复／工具提议的 Agent 流程。
- 无连接、准备中或环境不支持：文字流仍可响应，附带准确可用性说明，不提供执行工具、不宣称已执行。
- 终端开始与下一次派发仍分别重新检查真实就绪状态和当前 session/generation，不能因入口统一而绕过 ExecutionGate。
- 已有命令展示回执、精确危险审批、取消和秘密输入通路保留。一次只有一个 AI 写入者。

历史上下文从当前聊天读取，先脱敏再按字节限制裁剪；必须覆盖连续对话和上轮命令结果。只读恢复历史、跨目标旧聊天不能取得写入权。未知工具、多调用／不完整响应等保持失败关闭。

## 许可

统一能力许可需要明确模型 revision/destination 与目标服务器范围，以及普通自动执行和有限终端内容发送。每次用户输入不再重复申请，但配置或目标变化必须失效；终端动作授权继续绑定精确 session/generation/action。旧文字-only 配置同意不自动赋予终端能力。

## SSH 启动与协议

当前 `request_shell` 后向 stdin 注入 bootstrap 的方式不能直接自动化。新连接通过同一 PTY channel 的受控 `exec` 启动交互 Bash。临时 rc 来源为进程内管道／文件描述符，先完成 `.bashrc`，再安装受支持钩子；bootstrap 不写入终端输入队列。

解析器在启动请求前准备 nonce；先接收握手，再接收独立 ready。启动脚本阻塞时不向其自动输入。准备超时／环境拒绝／断线有明确状态，不重放 bootstrap，不开启日志。只有服务明确拒绝且确认未启动时，才可在同一通道进入手动 Shell；结果不明不能重复启动。

AI 动作统一使用 06 的顶层显式执行封装，真实 Begin/End 与提示符 Ready 分离；不要求 4.2 DEBUG 为任意语法提供 preexec。现代 Bash 手动日志使用受限 PS0；Bash 4.2 不安装 DEBUG trap，只在提示符观察到变化时记录缺口，不声称准确手动 Begin/End。真实 Bash 4.2.46、5.1、5.2 均为必要验收目标；旧版默认空 job-control trap 必须精确规范化，不能放过自定义处理器。

## 不变约束

禁止隐藏执行通道、输出静默推断完成、仅凭提示符文本批准执行、绕过危险审批、跨会话恢复写入权。前台结束不等于后台任务或业务目标完成。模型输出与远端文字都不具有批准权限。
