# 02 — 通用 Agent 与 Bash 兼容实现

日期：2026-10-16。本阶段补齐修订设计；精确提交的托管 CI、原生安装和实际升级仍待验证，不是发布声明。

## 实现

- 有界 foreground AST 保留原始文本，支持字面量命令、管道、条件／顺序列表、静态文件重定向。未知程序名、路径和外部脚本进入精确批准，不因不在自动清单而永久拒绝；整个 AST 合并风险，写入／未知分支不被短路免审。
- 常用 Docker、systemctl、grep 参数级分类；已识别持续流、交互上下文和 Shell 控制变更仍明确需手动。远端 scp／rsync 等网络数据操作需批准，不新增应用文件传输通道。
- 同一可见持久 Shell 顶层动作封装，原文与实际传输字节绑定审批；v3 动作身份、内容摘要、序号、Begin/End 和独立 Ready 相互核对。cd／export 保留，最长 8192 字节原文实际验证。
- 无 DEBUG 的 Bash 4.2 方案保留普通 Shell 行为；手动操作只标记提示符观察缺口，不能提供精确手动审计。AI 原文执行记录仍可使用。现代 Bash 保留已测 PS0 手动记录。
- 简化默认界面：一个输入框、三个模型字段、简洁动作确认卡；技术信息折叠。危险命令全文、目标和影响仍可核对。
- 内存输出有界分页、16 次一批／256 次累计预算、显式继续、UUID 去重和只读提交核对；不重发未知动作。输出窗口最多 1 MiB／动作、8 MiB／运行，缺失范围明确标记。

## 发现并修正的关键问题

1. 未知提交结果不能重新发送。UUID 回执只保留摘要与身份引用，不复制完整会话／动作快照；旧运行被替换后查询返回当前聊天证明，不重建旧任务。
2. 新秘密必须使所有仍保留的输出窗口失效，不只清空当前聊天。共享弱注册表覆盖跨聊天窗口；重复已有秘密不反复清空。分页前后不会泄漏旧窗口中的后来已知秘密。
3. 页中仍有数据与采集完成是两回事。has_more 控制翻页，complete 表示采集窗口结束；已完成长输出可读取到末页。
4. 同一个 PTY 数据块必须先进入脱敏观察窗口，再发布 End/Ready 通知，防止并发完成处理先关闭窗口而丢失最后输出。
5. 控制 helper 不依赖可被函数遮蔽的裸 local／return；保留命名空间冲突和篡改检查。
6. 4.2 DEBUG 原型测试失败且影响部分手动状态，最终放弃该路径，而非放宽测试。手动观察缺口仅在没有待派发／活动 AI 时可等待独立 Ready 恢复；钩子篡改和 AI 结果未知不能通过此路径恢复。
7. 累计规划预算不随每批继续清零，避免动作和输出元数据无限增长。

## 仍需诚实保留的边界

不是任意 Bash 脚本沙箱，不支持所有嵌套／展开／后台交互语法。允许未知程序尝试也不证明它一定结束或没有副作用。4.2 手动日志是提示符观察，不是精确命令审计。真实用户桌面、外部模型提供方和用户服务器配置不能以本地或模拟测试代替。
