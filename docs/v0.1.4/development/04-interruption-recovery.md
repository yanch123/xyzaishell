# 04 — 命令接收中断恢复

日期：2026-10-16。状态：本地完整回归通过，等待本次精确提交的平台 CI；尚未发布。

## 发现的问题

候选 `07e882ab` 的 CI 共 12 项作业，11 项通过。Bash 4.2／5.1／5.2 的真实 OpenSSH、浏览器 18 项、原生生命周期 15 项和两平台安装包均通过；Bash 5.2 的部分命令帧接收期间 Ctrl+C 测试偶发失败，因此不能发布。

原生 Bash 最小示例和实际接收器均复现：中断后提示符清理可能推迟到另一次输入，终端模式没有及时恢复。测试保持原有等待上限，禁止通过补发回车、放宽断言或盲目重跑来掩盖。

## 最终修正

- 接收期间临时使用 `noflsh`，减少中断与终端输入／输出冲刷的竞争。
- 临时 INT 处理器明确退出接收函数；在内建 read 完成回退后的提示符清理中恢复保存的完整终端状态与原默认 INT 行为。
- 恢复前有界清理当前已排队的接收字节，防止残留注释吞掉下一条手动命令。不等待未来数据、不重放命令。
- Bash 4.2 保留一次有界读取，避免该版本分段超时丢失已接收字节；现代 Bash 使用有总截止时间与次数上限的短读取，完整保留分片。
- 8192 字节原始命令与 128 KiB 传输上限不变；成功执行前恢复原终端和信号行为。

详细协议及手动输入竞争边界见 [08](../08-quiet-command-transport.md)。以上全部自动处理，不增加用户设置。

## 已完成的本地验证

- 实际 Bash 4.2.46、5.1.16、5.2.37：各 47 项完整 PTY 测试通过。
- 另有 480 次中断压力测试全部通过：每个版本 160 次，分别覆盖 C／C.UTF-8、握手后立即中断和部分输入后中断。

- 最大长度执行、近最大长度中断、跨读取片段输入、后续第二条动作、后台输出和超时测试通过。
- Rust 全套：288 个单元测试、80 个对话／SSH 回环／终端集成测试通过；严格 Clippy、格式与差异检查通过。默认跳过的专用真实 OpenSSH 测试仍由精确提交 CI 验证。
