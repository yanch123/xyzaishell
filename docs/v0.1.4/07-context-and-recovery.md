# 07 — 上下文和恢复设计

状态：修订设计，最终实现和测试需逐项对齐。内部机制不转化为主界面的配置负担。

## 同一对话持续工作

每轮模型获得当前用户目标、必要聊天前文、已确认执行事实、模型推测、剩余步骤、当前终端能力和相关输出。事实附来源；模型判断与宿主记录的开始／退出码／就绪分开。

命令后模型决定继续、完成、提问或请求操作；不能只返回命令后就退出，也不能因退出码 0 自动宣布用户目标达成。后续追问能够引用刚才的检查结果。

## 有界保留，不凭空忘记或补全

当前进程内按 action 保存有界输出窗口及引用，长输出按块读取／摘要，而不是只截 512 字节就把其余当作不存在。固定默认：单动作脱敏输出窗口最多 1 MiB，当前运行总量最多 8 MiB；超过单动作上限淘汰该动作最旧块，超过总量上限优先淘汰已完成动作的最旧块，再淘汰当前动作最旧块。绝不覆盖动作身份或伪装完整，保留 earliest_offset 和 gap。单轮模型请求序列化上限 60 KiB，优先保留本轮请求、当前动作状态和近期相关证据，裁剪摘要明确标注。

读取已捕获输出是本地取数工具，不是重新运行命令。固定接口 read_action_output(run_id, action_id, offset, max_bytes)，max_bytes 为 1–16384；offset 是脱敏后 UTF-8 字节偏移，必须是字符边界。返回 text、next_offset、earliest_offset、complete、truncated、gap；超出保留范围返回缺口与可用起点，不隐式重跑。只允许当前聊天／目标授权范围内的当前 run 数据，其他运行／会话／失效引用拒绝。分页有界，读到末尾不代表远端业务成功。已丢失的内容不能虚构为可读取。秘密在存储／裁剪／编码前处理，未知秘密仍需用户审阅。默认不持久保存原始终端输出；日志、聊天历史的开关保持独立。

## 运行预算

固定每批最多 16 次模型规划响应，每响应最多一个工具；上下文更新、输出读取和命令提议均消耗一次规划次数。命令前台等待默认 5 分钟后转结果未知，不自动打断或重发。每次模型请求使用现有请求超时设置。用尽预算时显示“已处理一轮，需要继续吗？”并保留目标、事实和剩余步骤；显式继续只将本批规划计数归零，增加最多 16 次新规划预算；保留累计次数、上下文、动作 ID、输出偏移和已用审批。只有本地没有派发结果不确定的动作且当前 Shell 独立就绪时才能继续；不重发结果未知命令、不复活旧批准。取消／换目标／重连不具有续预算效果。

没有足够上下文或可靠结果时提问，不能假装已完成。模型供应商错误、认证错误或工具格式不兼容应有明确短提示，诊断细节折叠显示。

## 恢复规则

- 发送之前明确失败：可修正后重新提交。
- 发送响应丢失／写入结果未知：先只读核对真实状态，不自动或重复点击重发同一动作。
- 使用客户端提交 ID、宿主 run ID 和 action ID 关联消息，避免仅凭脱敏后文字相等判断是否已接收。
- 重连后建立新的连接身份和就绪证据，旧批准和未完成写入不能迁移。
- 同一服务器的历史可供讨论，但不证明当前状态；更换服务器不自动沿用另一台服务器的执行权限。
- 用户停止时立即停止新增规划和写入；远端程序是否终止单独报告。需要中断时使用明确 Ctrl+C 动作，不暗中发送。

## 最小可交付场景

同一聊天依次完成：问候 → 检查磁盘 → 根据结果追问 → 查看有限服务日志 → 解释故障 → 提议重启 → 拒绝时零执行／批准后单次执行 → 复查结果。覆盖无 SSH、旧 Bash、错误返回、超时、断线和响应丢失。界面必须保持一个输入框和清楚的执行记录。
