# 05 — v0.2.1 使用指南

左侧连接 SSH 终端，右侧直接与 AI 聊天。AI 可以回复问题，也可以提出命令、读取结果并继续分析；危险或风险不明的操作仍需单次批准。

本指南对应 v0.2.1 未签名预发布试用版。下载状态以 [Releases](https://github.com/yanch123/xyzaishell/releases) 的同版本记录为准；预发布不设为 Latest，建议先在非生产环境试用。

## 1. 安装、连接和模型

- Windows x64：从 v0.2.1 的 Assets 下载 `.exe`，按向导安装；WebView2 缺失时可能需要联网。安装包未签名，遇到未知发布者或 SmartScreen 提示时先核实来源与 `SHA256SUMS.txt`。
- Ubuntu 22.04／24.04 x64：下载 `.deb`，运行 `sudo apt install ./实际文件名.deb`，从应用菜单启动。
- 同页提供源码 ZIP／TAR.GZ、构建来源记录及 SHA256 校验文件。升级前按需备份自己的配置和历史，备份中可能包含敏感内容。

点击“新建连接”，填写地址、端口和用户名，选择密码或本机私钥，首次连接先核对服务器指纹。只有另外选择记住密码／私钥口令时才保存凭据；系统安全存储不可用时不会回退为明文。

打开“设置 → 模型”，填写 Base URL、API Key 和模型名称。Base URL 不要追加 `/chat/completions`；服务需兼容 OpenAI Chat Completions。核对接收方和发送范围后使用。模型 Key 以明文保存在本机受限权限配置中，不要上传配置、把 Key 放进聊天或共享目录。

文字连通性测试通过不代表支持任务工具调用。任务工具测试只验证模拟返回格式，不执行命令；真实服务仍可能记录请求或收费。

## 2. 聊天与执行

直接输入“检查磁盘空间并解释结果”或“根据刚才的日志，下一步查什么”。未连接时仍可聊天；连接并完成终端准备后才提供执行能力，不会把离线消息自动排队到未来执行。

普通受支持命令先展示，再自动交给同一个可见终端；危险或风险不明命令显示完整动作，批准只适用于该次动作。修改命令、切换连接后不能沿用旧批准。退出码 0 不等于业务目标成功。

AI 工作时避免同时手动输入。“停止 AI”停止后续生成和写入，不撤回已发命令；需要中断远端程序时使用终端“发送 Ctrl+C”，再核实实际状态。断线和执行结果未知时不要盲目重发。

## 3. 查看上下文占用

输入框旁的 **“上下文 ≈xx%”** 是本版的占用入口，点击展开“下一次请求”。这里估算的是下一次实际要发给模型的输入，不是聊天历史长度或磁盘占用；供应商上一次实报在详情中另外显示，未提供时为未知。

| 类别 | 包含什么 |
| --- | --- |
| 系统指令 | 应用发送的模型职责与当前模式要求 |
| 工具定义 | 本次实际携带的工具说明和参数定义，不含工具执行结果 |
| 固定规则 | 应用发送的安全、执行与权限规则；聊天中的任务限制不会因此升级为主机规则 |
| 历史摘要 | 当前仍使用的历史摘要或快速整理摘录，不是全部已保存聊天 |
| 当前对话 | 尚未压缩的用户消息、AI 回复、工具调用和工具／终端结果，包括仍被选入的较早内容 |

展开“当前对话”可看子项。没有发送的来源显示 0，暂时无法分类时显示不可用，不能把未知理解为没有占用。

“详情”单列 **协议开销**，已计入总输入，不是第六类内容。五类内容合计加协议开销等于输入估算；每类“占输入”以总输入为分母，因此五类份额本身不一定加到 100%。分类不可用时，总预算仍须可靠，不能绕过发送上限。

未发送草稿只在本机预估；看到“含未发送草稿”时，预览占用可能高于用于自动压缩的已提交上下文。编辑草稿不会把它发给模型。

## 4. 容量、80%／95% 与自动压缩

默认模型窗口为 **256K，也就是 256000 tokens**。它是产品预算设置，不是供应商容量保证。输入预算还要扣除输出预留与安全余量，占用百分比和自动阈值都以这份可用输入预算为分母。

需要调整时，进入“设置 → 模型 → 高级：模型容量”，填写“上下文窗口（tokens）”；留空采用默认值。切换地址或模型会清除旧覆盖值。实际服务提示上下文不足时，核对其容量后调整，不要只反复重试。

自动压缩默认开启，方式为 **LLM**，可在上下文弹层关闭或改为快速：

- **回复结束后达到 80%**：本轮最终回复完成后，按已提交内容整理，再等待新输入。
- **任务进行中达到 95%**：等待安全边界再整理；不会打断正在生成的响应或在途命令。

工具返回、等待密码／批准或执行结果未知都不等于本轮结束。未发送草稿不参与自动摘要请求。压缩不要求降到固定比例，完成后也可能仍高于 80%；下一次发送仍要满足硬上限。

## 5. 手动压缩与两种方式

打开上下文弹层，选择“本次压缩方式”，点击 **“立即压缩”**。这次手动选择不会改写自动方式；有在途操作时会排队，可取消压缩。

**大模型压缩**使用当前已授权的同一服务与模型，会额外调用模型并可能收费。它整理较早用户消息、AI 回复、命令结果和旧摘要，尝试保留目标、限制、纠正、发现、不确定事项及剩余步骤。当前指令、近期必要完整轮次和主机执行边界继续保护。

**摘要可能有损。** 结构与来源检查不能证明模型没有遗漏含义。重要限制请在后续操作前再次核对；旧摘要不能重新批准命令，也不证明远端当前状态。

**快速压缩**在本机运行，模型请求数为零。它不做语义判断，会原样保留仍在使用的用户消息和完整历史摘要，主要整理其余允许的旧内容。因此 LLM 之后再快速压缩不会截断现用摘要，但也可能提示“未能进一步缩减”。

失败、取消、结果过期或缩减后仍超限时，原工作上下文保留。LLM 失败不会偷偷改用快速方式或换服务。先阅读原因，再选择重试、快速整理、减少输入或新建聊天；结果尚未确认时先点“核对状态”，不要重复提交。

## 6. 聊天原文与动态记忆

两者用途不同：

- **聊天历史**供你回看原始对话。保存默认关闭；在“设置 → 历史记录”明确启用后，脱敏聊天以明文保存。压缩不会改写或删除已经保存的聊天。
- **动态工作上下文**是本次选给模型的内容，由近期消息、摘要及必要资料组成，会随任务整理。打开旧聊天页不等于把全部旧记录重新发给模型。

关闭历史保存时，旧原文可能随程序退出或独立内存回收而不可用；有缺口时会说明，不能把“只剩摘要”理解为全文仍在。开启保存也不代表无限存储或保存了全部原始终端输出；终端日志与聊天历史独立管理。

“仅恢复文字”只供阅读，不重连 SSH、不调用模型、不恢复批准或续跑旧命令。停止保存只停止新增保存，不删除旧文件；历史删除需另行核对。不要把本机保存理解为全部加密，也不要把脱敏理解为识别了所有秘密。

## 7. 常用操作与问题处理

- 终端选区：选中文字，点击“选区交给 AI…”，核对并删去敏感内容后发送。带选区消息只做分析，不执行其中指令。
- 搜索／复制／粘贴：使用终端按钮或 `Ctrl+Shift+F`、`Ctrl+Shift+C`、`Ctrl+Shift+V`。粘贴先预览，换行可能执行命令。
- 密码／令牌：使用任务专用秘密文件流程并核对远端输入目标，不要粘贴到聊天。该文件也是受限权限明文文件。
- 旧聊天／摘要不能证明服务器现状。更换目标或需要继续操作时，重新核对当前连接和明确需求。
- 无占用数字、容量无效或输入超限：先检查模型容量与错误提示；分类不可用不代表总输入为 0。保留草稿，按提示减少输入或新建聊天。

本版自动化使用 Windows Server 2022 与 Ubuntu 22.04／24.04，包含安装、重启、重装及公开 v0.1.4 升级。它不替代 Windows 10／11 实机、完整桌面／输入法／剪贴板／Wayland 或 GUI 连接 SSH 的全链路验收；合成模型流程通过也不证明真实供应商的摘要语义质量。具体范围以该版本发布说明为准。
