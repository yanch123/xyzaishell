# 01 — 需求与交互

状态：**设计，尚未实现**。本文件定义 v0.2.1 增量；现状与接口差距见 [02](02-architecture-and-interfaces.md)，验收见 [03](03-acceptance-and-delivery.md)。

## 1. 五类内容

继续使用输入框旁的上下文入口。弹层按固定顺序显示以下五类；不存在的来源显示 `0 · 本次未发送`，不为凑类别插入内容。

| 类别 | 真实来源边界 |
| --- | --- |
| 系统指令 | 程序构造的模型职责、当前模式及回答要求；不等同于整个 system 角色消息 |
| 工具定义 | 实际请求携带的工具名称、说明、参数 schema；工具调用与结果不属于此类 |
| 固定规则 | 程序维护并实际发送的安全、执行与权限规则，以及摘要输出契约；不是从用户文字提炼的“规则” |
| 历史摘要 | 主机已提交生效、进入当前投影的摘要；包括 LLM 摘要和明确标记的快速历史摘录 |
| 当前对话 | 当前请求仍携带的未压缩用户消息、AI 回复、工具调用、工具／终端结果；“当前”包含未压缩的较早轮次 |

“当前对话”可展开为用户消息、AI 回复、工具调用、工具／终端结果、其他实际输入（如显式选入的材料、主机只读状态）。子项互斥且合计等于父项，展开不额外计量。规划请求的 `user_instruction` 仍属于用户消息；不能把旧 `goal_constraints` 直接改名为固定规则。目标、身份、生命周期等内部状态继续保留，其归类不赋予执行权限。

用户或终端输出即使包含摘要前缀、规则口吻或 JSON，也按主机记录的真实来源分类。系统指令与固定规则可能在同一 system 文本中：由构造器标记各自片段，不能按字数比例拆分旧 `rules_tools` 总量。

固定规则本版仅指主机已有代码／设置提供的规则，不新增规则编辑器、永久记忆、Skills 或 MCP。聊天中的“不要重启”等任务限制始终是对话／摘要内容，模型提取后也不升级为主机规则。日常弹层仅保留五类占用和必要协议说明，技术对账放在折叠详情。

## 2. 总量和交互

- 主指示继续显示“可用输入预算占用”：`I / B`，与自动触发同口径。下一请求估算、供应商上次实报和压缩调用用量分开。
- 五类是内容分类。协议包装及明确标注的未知服务端模板工程余量在详情单列“协议开销（估算，已计入总输入）”，不新增第六个内容类别，不隐藏、不重复归入五类。
- 对账式为：`五类内容合计 C + 协议开销 O = 总输入估算 I`。每行“占输入”仍以 I 为分母；五类份额加协议开销份额才为 100%。构成条保留可辨识的协议余量留白并给出文字说明；不得把五类重新归一化为 100% 后仍标“占输入”。详情显示 C、O、I 的整数与等式，避免约数和舍入掩盖差异。
- 输出预留 R、安全余量 S 在输入构成之外；协议 O 已在 I 内，不能再从 B 扣一遍。供应商未公开的模板不是实测数据，界面不能宣称精确 token。
- 保留手动 LLM／快速、自动开关、排队／取消／失败／过期提示、键盘展开与焦点恢复；无需新增常驻配置。只读历史不能压缩成可执行上下文。

## 3. LLM 压缩旧用户消息

较早且已离开保护窗口的用户消息可以与旧 AI 回复、命令结果一并交给当前已授权模型总结，不再全部永久保护原文。固定摘要要求保留：目标、限制与禁止、后续纠正及取代关系、已确认事实及证据、不确定事项和剩余步骤；不得把猜测升格为事实，把退出码 0 当作业务成功，或把旧事实直接视为当前服务器状态。

当前指令与当前轮、近期必要完整轮次（沿用最近两完整轮）、系统指令、固定规则、工具定义、未闭合工具单元，以及主机要求保留的执行／证据依赖继续保护。模型只整理历史资料，不能改写主机身份、权限、审批、停止／未知状态或规划计数。

摘要是**可能有损的模型解释**。程序可以验证 schema、来源覆盖、引用、保护项、预算与原子提交，不能证明语义无遗漏；来源全部列出也不等于所有限制已被正确理解。提示应说明“旧消息已由模型整理，可能遗漏细节；原文可用性以历史保存状态为准”。不声称无损、永不遗忘或恢复原有授权。

## 4. 快速压缩的保守边界

快速方式没有语义判断能力。本版选择最小保守方案：除通用保护集外，**原样保护所有仍在投影中的 UserInput 和所有现用历史摘要**。包括没有 `user_constraints` 条目、只在自由文本中保留限制、元数据不完整的旧摘要；不信任模型自称“无约束”来放行裁剪。

不能把 LLM 摘要交给现有约 160 字符头尾截取，不能截坏摘要 JSON，不能通过摘要嵌套或重复 quick 丢弃用户约束。quick 仍可处理其余允许的旧 AI 回复、闭合工具结果／日志，保持省略标记；若受保护内容过大或没有收益，明确无收益／需要调整，保留旧投影。不做新的结构化快速语义摘要算法。

LLM 后续可以连同新旧历史整理现用摘要，但仍受当前保护集、来源谱系、同源自动去重及模型调用上限限制。不能仅因生成新摘要 ID 就反复自动压缩。

## 5. 不变项

默认窗口 `256000` tokens；容量来源优先级和输出预留沿用 v0.2.0；默认自动 LLM；轮后 `80%`、轮中 `95%`，同一输入预算分母；无固定压缩目标比例。严格缩减且最终请求满足硬预算时允许 `90% → 85%`，不要求低于触发阈值。字节软占比不触发压缩；实际硬超限按现有安全点机制处理。

LLM 摘要仍使用当前已授权 provider／destination／model，不新增密钥或工具能力；每作业最多 8 次请求／120 秒，各分块及合并请求都预检。quick 模型请求数为零；LLM 失败不自动回退 quick。草稿只在本机预估，不自动上传。

失败、取消、过期、无收益或仍超硬预算时保持旧投影。成功仅原子替换活动上下文，不写执行权限，不补跑命令。聊天原文归档与动态上下文独立，压缩不改写已保存聊天；历史保存默认关闭保持不变，内存回收、已归档缓存卸载和无归档原文过期各按既有独立策略处理，并如实标明可读性或缺口。
