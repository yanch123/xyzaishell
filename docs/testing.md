# 测试与验收计划

版本：design-v0.1。下列用例均为后续实施的验收要求，**应用尚未实现，所有应用测试状态均为未执行**。文档链接和 TOML 解析检查不属于应用测试。

## 1 环境与证据

- Windows 10 22H2 x64、Windows 11 x64：分别记录系统构建号、安装方式、WebView2 和应用版本。操作系统兼容性不等于操作系统仍获常规安全支持。
- 可重置 Linux SSH 测试主机：记录 SSH 服务版本和 Shell。起步可用 Bash；其他系统及 Shell 逐项登记结果，不宣称全部 SSH 服务自动化兼容。
- 模拟模型服务：能回放 SSE、工具参数分块、超时、限流、格式错误和取消后的迟到事件。最后针对用户选定的真实兼容服务再做验证。
- 测试凭据只能使用专用虚拟值，禁止对生产服务器运行破坏性测试。涉及付费模型、外部数据发送或系统安全配置，测试前另行落实权限和预算。
- Windows 构建、真实 Windows 界面验收和 Linux SSH 目标测试是三类不同证据。不得以一种替代另一种。

每次执行记录：提交 SHA、依赖锁文件版本、测试用例、环境、实际结果、通过／失败／阻塞／未执行、脱敏证据和残余限制。未知不计通过。

| T-16 | FR-16 | 模型响应后停止任务，旧回调随后到达 | 后续 AI 动作失效；停止 AI 不伪称远端程序已终止 |
| T-17 | FR-16 | 在发送前、发送中、副作用后及返回结果前断线／崩溃 | 状态区分未发送与结果未知；没有盲目重放；重连生成新连接代次 |

## 3 安全针对性测试

### 3.1 授权与输入来源

向模型提供伪造的“用户已经批准”终端输出、日志中的指令、隐藏控制字符和修改后的工具参数。验证审批只能来自真实用户界面动作，模型不能调用人工输入接口。审批重放、跨任务复制、跨服务器复制均失败。

人工直接输入的命令不经过 AI 审批；测试不能把此产品决定误判为模型绕过。模型获得该通道权限才属于缺陷。

### 3.2 任务秘密

虚拟值覆盖空格、单／双引号、美元符号、换行及控制字符。安全编码不明确时禁止自动拼接，并显示可由用户处理的阻塞原因。不能以调用成功证明秘密未进入远端历史或进程列表；必须单独说明这些远端暴露限制。

用户确认前只记录字段名和存在状态。配置读取失败、解析失败、模型认证失败、SSH 认证失败时均不得打印完整原文或请求头。

### 3.3 不可靠网络与恢复

采用可控断网或模拟流错误，覆盖动作送出而结果未到的窗口。验证恢复历史不会自动恢复原来的远端任务；未知结果要通过查询或人工核实，不能因为模型建议“再试一次”就重发。

### 3.4 前端与远端不可信内容

用带 HTML／脚本的 AI 文本、异常终端标题、特殊链接协议、剪贴板控制序列验证不会触发额外本机权限。检查前端 IPC 权限，不仅检查 UI 是否隐藏按钮。

## 4 协议和契约验证

- 每个接口的缺失字段、未知枚举、过期 generation、错误 task_id、重复 request_id 和取消路径均需覆盖。
- 工具请求与结果的关联 ID、事件序列和输出截断标记须可验证。
- 配置 schema_version 的未知版本拒绝静默降级；示例与真实解析器做相同校验。
- 决策适配器返回的是评估，不是授权；unknown 和服务不可用均不得放宽规则。
- 对 prepare 与 dispatch 之间的内容或配置变化进行重复验证，不能仅在 UI 展示时检查一次。

## 5 性能与稳定性

首轮建立基线后再冻结指标；目前不虚构性能目标。至少测量启动时间、空闲内存、滚动输出吞吐、手工输入延迟、模型上下文大小、单任务步数与模型调用成本。对长时间 tail、连续错误、模型无限建议下一步设置可配置上限并给出用户可见停止原因。

高负载测试应确认 UI 可用、停止按钮可操作、内存有界、截断有标识，不以悄悄丢弃重要输出获得虚假的响应速度。

## 6 发布门槛

1. 首批支持环境的基础、授权、凭据、断线和安装用例有实际通过证据。
2. 没有未说明的 P0 阻塞；不能将用户明确延后的复杂判断重新当作必须实现的 P0。
3. 正常状态、失败、待确认和结果未知在 UI 中可区分。
4. 无真实秘密进入仓库或测试产物。
5. 依赖和安装包来源可追溯，适用的许可证、签名与 WebView2 分发策略完成核验。
6. 未覆盖的 Shell、模型和 Windows 场景写入发行说明，不默认为支持。
