# 02 — 终端日志架构与采集边界

## 数据路径

当前可见 SSH PTY → 有界 Shell 协议解析 → 独立日志服务 → 独立 SQLite → 查看与 JSON/CSV 导出。

此路径不依赖 AI 任务、聊天历史或模型配置。没有日志回放/执行入口，远端数据永远不能授予命令权限。日志协议元数据从模型观察流剔除，原始 PTY 显示和背压确认仍保持一致。

## 首期 Shell 支持

用户确认当前终端空闲且位于兼容命令提示符后，应用通过同一个可见 PTY 写入启动命令，启动 Bash 4.4+ 专用交互子 Shell。外层启动语句使用 POSIX 兼容引用；仅在内部 Bash 使用 process substitution。没有隐藏 exec、SFTP 或远端持久化脚本，也不修改远端启动文件。

子 Shell 使用干净启动配置，启用无过滤、保留多行的进程内 history，禁用历史文件写入。通过 PS0 在完整顶层命令读入、执行前发 begin，通过 PROMPT_COMMAND 返回后发 end。不用 DEBUG trap 或 BASH_COMMAND 拼凑完整命令。

独立子 Shell 不继承父 Shell 未导出的 alias/function 或交互配置；exit 返回原 Shell。支持一次顶层交互命令文本，不是变量展开后的 argv，不展开脚本内部命令、后台进程或嵌套 Shell。密码提示、编辑器、REPL 的输入不作为命令记录。

history 被关闭/改写、事件过大、顺序不一致等必须产生缺口或未知状态，不能以旧记录或键盘输入补齐。远端可禁用 hooks 或伪造事件，因此这不是服务器防篡改审计。

## 协议

ESC ] 777;xyzlog;1;nonce;kind;fields BEL。nonce 是每次启用随机的关联标记，不是认证凭据。

- H：握手及 Shell 版本。
- B：Shell 序号、远端 epoch 秒、执行前物理 cwd、完整命令；文本为严格 Base64/UTF-8。
- E：匹配序号、远端 epoch 秒、Shell 返回码。
- G：缺口原因，不伪造命令。

命令最多 16 KiB、cwd 最多 4 KiB、协议帧最多 32 KiB。解析器需覆盖任意拆分、粘连、错误 nonce、无效字段、控制符、未闭合帧与超限恢复。错误不能包含原始日志或秘密。收到 B/E 时分别记录本机时间；远端时间是未验证的报告，界面明确区分。

## 存储与生命周期

独立 shell-log.sqlite3，不修改 v0.1.0 聊天历史结构。复用已有安全目录和跨进程锁，SQLite 使用有界容量、严格 schema、事务和防御设置；存储失败显式停止记录，但不阻塞 SSH。

默认禁用；启用仅覆盖之后事件。暂停不保存待恢复缓冲；暂停期间的命令不补录。断线/退出时未匹配结束的命令标未知。重连不自动启用，也不复用旧 generation。

已知秘密在入队前、落盘前、展示/导出时过滤，但未知/变形秘密无法保证识别。日志为本地明文，执行敏感命令前需暂停。支持两个应用实例独立采集并安全访问同一数据库。

## 导出

固定本地私有导出子目录 shell-log-exports，使用随机新文件名，拒绝覆盖，不接受前端任意路径。返回实际保存路径、记录数、字节数。筛选结果使用固定快照，避免导出期间的新事件造成重复或遗漏。

JSON 是含版本与导出时间的规范文本格式；CSV 是电子表格安全展示格式，转义引号/换行并防止所有远端可控文本触发表格公式。默认不保存/导出终端输出正文。
