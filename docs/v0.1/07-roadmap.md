## 2 实施前待确认事项

这些项目不阻止阅读或评审文档，但不得默认为用户已批准：

1. 最终技术栈与配置字段冻结，具体环境变量名及默认目录。
2. AI 上下文发送范围、首次启用提示、记录保留期限及是否持久化聊天。
3. 首批验收用 SSH 服务和 Shell 列表，以及可使用的 Windows／Ubuntu 构建与真实桌面测试环境；Ubuntu 版本目标已确认，具体桌面、X11／Wayland 和输入法矩阵仍待冻结。
4. 两平台是否需要完全离线安装；Windows 建议 NSIS setup.exe／WebView2，Linux 建议 `.deb`／WebKitGTK，AppImage 可选；验证最旧目标兼容构建基线与运行依赖。
5. 代码签名身份、分发方式、项目许可证；不默认购买证书、不生成未授权凭据。
6. 具体模型服务的 tool calling／SSE 兼容性，主机认证方式及必要的企业网络约束。
7. 任务配置路径是否要求手工选择，XDG／Windows 路径提案、Linux 安全存储提供者与仅进程内存模式、重新录入式跨平台迁移流程。

## 3 开发顺序与交付关口

### M0 文档评审

交付需求、架构、接口、配置示例、安全约束、测试计划。核对确认需求与建议默认值，完成必要决策后再冻结实施基线。文档校验只能证明结构和一致性，不能证明程序行为。

### M1 普通 SSH 客户端

从开始就建立共享核心／平台适配边界，在 Windows 和 Ubuntu 上建立 Tauri 桌面骨架和 Rust 会话层，完成连接、认证、主机密钥校验、终端显示／输入、窗口尺寸与断线状态。实现每实例单服务器，验证多个实例独立连接。先验证正常 SSH 使用，暂不接模型。

通过条件：测试计划中的基础 SSH 与 Windows／Ubuntu 冒烟项通过；状态未知不伪造连接成功或命令成功。

### M2 模型与任务

完成模型配置加载、连接测试、聊天流式响应、会话内多任务管理、上下文长度与数据披露。基于锁定版本接入 Rig，先用模拟模型做协议回放，再测试选定服务。不得把模型返回的部分工具参数提前执行。

通过条件：模型错误、取消、超时、不支持工具及输出截断能正确展示；当前任务不读取其他任务凭据。

### M3 自动动作与授权

将模型工具请求接入同一个可见 PTY，实施单 AI 任务所有权、准确动作预览、基础策略、用户授权、明确未知状态、结果未知后禁止自动重试。只预留决策接口，未接入时依靠保守基础策略与人工确认。

通过条件：测试授权不能被另一任务、旧连接、变更命令或重放请求复用。用户输入按普通终端行为转发，不测试或宣称自动人工仲裁。

### M4 凭据、持久化与异常恢复

实现三类配置、任务秘密引用、Windows DPAPI／Linux 安全存储及用户显式选择的会话内存模式、平台路径／权限和原子保存、脱敏、最小审计和非秘密任务持久化。恢复历史时不重放不确定远端动作。秘密无法安全注入的场景改由用户处理。

通过条件：四份配置样例、真实实现 schema 和文档一致；两平台秘密边界、keyring 不可用、保存结果未知与断线测试通过；残余外部暴露边界明确。

### M5 Windows 与 Linux 发布验证

分别构建 Windows 与 Linux 产物。Windows 验证拟议 NSIS setup.exe、WebView2 和系统构建号；Linux 验证拟议 `.deb`、运行依赖和兼容构建基线，AppImage 只有单独通过测试才作为补充发布。两平台覆盖安装、升级、卸载、中文输入、缩放、干净配置及多实例；Ubuntu 22.04／24.04 均须真实桌面验收。

通过条件：同一精确源提交和锁定依赖对应两平台证据，并提供未覆盖发行版／桌面／Shell 的说明。容器单元测试、Linux SSH 服务器测试和 CI 编译都不能代替客户端安装及界面验收。代码签名、包校验和发布方式另行确认；文档阶段不生成或上传应用安装包。

### 后续可选能力

Jev／其他决策服务、更多 Shell 适配、复杂交互识别和更丰富的任务复核。保留可替换接口，不把某个外部模型变成首版必需依赖。SFTP、本机终端和多服务器 Agent 编排不在当前范围，新增需另行确定。

## 4 提交与质量管理建议

采用文档先行、模块化小变更；实现阶段每个变更附对应测试结果与剩余风险。模型服务、SSH 主机和真实凭据不写入代码仓库。开发分支和 PR 策略在实施时确定，不因文档上传自动开启部署、发布或付费工作流。

性能指标必须在首批基准测量后确定；不虚构启动时间、内存、并发量或 token 成本。阶段完成以验收证据为准，不以页面能打开或一次正常执行为准。
