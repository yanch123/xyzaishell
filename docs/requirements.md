本文定义 xyzaishell 的产品范围、可观察行为和后续验收依据。当前交付为文档阶段，没有已实现功能、可安装程序或已通过的运行测试。这里的「必须」描述未来实现的约束，不表示功能已经存在。

## 2. 产品目标与角色

目标是让熟悉 SSH 终端的人，在保留日常终端操作方式的同时，将明确的远程任务交给 AI 执行。AI 能看到经过筛选的终端上下文，说明下一步，调用受控工具，并根据结果继续。

主要角色与责任：

- **用户**：选择服务器与模型目的地、下达任务、处理授权/未知状态、填写任务密钥，并自行安排手工输入与 AI 执行的时机。
- **AI 任务运行时**：理解任务、生成命令或交互提案、依据工具结果更新计划。模型输出本身不产生执行权限。
- **桌面宿主**：管理 SSH、配置、凭据、AI 写入权、授权、终端输出和记录；负责真正的网络及终端 I/O。
- **远程 SSH 服务与 shell**：执行收到的字节；其回显、输出和提示符均是外部数据。
- **模型服务**：接收用户同意发送的上下文并返回推理结果；它与 SSH 服务器可能属于不同组织。

「类似 Xshell / Cursor」只描述交互方向，不表示复制其完整功能、视觉设计、兼容性或商标。

## 3. 范围

### 3.1 首版范围

1. 可安装的 Windows 桌面壳、双栏界面和基本设置。
2. 单连接 SSH 交互终端：输入、粘贴、显示、滚动、窗口尺寸同步与连接状态。
3. 多 AI 聊天、任务切换、受控的模型驱动执行。
4. 一个 AI 写入者、基础高风险授权、未知状态暂停、失败后的保守恢复。
5. 三类独立配置、任务密钥缺失提示、受限的上下文与操作记录。
6. 决策模型扩展边界及可替换组件接口。

### 3.2 明确不做

- 本地终端、本地 PowerShell、WSL、本地任意命令执行工具。
- SFTP 面板、文件浏览/传输、上传/下载、拖放文件传输。
- 单个实例内的多个并行 SSH 会话、分屏服务器编排、跨实例 AI 锁。
- AI 绕开可见 PTY 的 SSH exec/subsystem 工具或第二条执行会话。
- 根据手工按键自动暂停 AI、自动恢复、自动夺取控制权、保证人/AI 输入不混杂。
- 首版 Jev 实现、复杂自动判定系统、全 shell 命令边界协议或强制远端 shell 注入。
- 未经另行确定的端口转发、跳板链、代理、团队共享、云同步或插件市场。

远端 shell 本身可运行多种命令。上述「不做上传/下载」指不提供文件传输能力或绕过工具边界的文件传输工具；它不构成对远端命令行为的隔离保证。命令可能传输数据时仍须经过对应风险和目的地授权。

## 4. 功能需求

### FR-01 Windows 安装目标

**状态：已确认；安装细节待定。** 面向 Windows 10/11 x64 提供可安装程序。安装、首次启动、正常退出和卸载应有验收记录。具体系统版本、安装器形式、签名方式、WebView2 分发方案在发布阶段确认。

### FR-02 双栏终端与 AI 聊天

**状态：已确认。** 左侧是正常交互终端，右侧是任务聊天。应可辨认当前服务器、连接状态、当前聊天以及持有 AI 写入权的任务。切换聊天不切换服务器，也不隐式停止原任务或转移 AI 写入权。具体布局尺寸、主题、快捷键属于后续 UI 设计。

### FR-03 单实例单 SSH

**状态：已确认。** 每个实例最多有一个活动 SSH 连接和一个供人/AI 共用的交互 PTY。连接第二台服务器应在另一实例进行，或在当前实例明确断开并替换连接。不同实例之间不共享终端状态和 AI 任务写入权。

### FR-04 同一个可见执行通道

**状态：已确认。** AI 操作写入用户正在看的同一个 SSH PTY，结果进入同一终端输出流。不得以「提高可靠性」为由在后台新建 exec 通道执行用户未看到的命令。UI 的命令卡片可以展示结构化提案，但不能替代真实 PTY 输出。

### FR-05 多聊天、独立任务

**状态：已确认。** 每个聊天有独立任务标识、目标、消息、状态和任务密钥引用。任务可以保存/查看各自历史；不自动向其他聊天注入其私有历史或密钥。所有任务共享同一远端环境，前一任务造成的目录、进程或文件变化可能影响后一任务，不能声称远端环境隔离。

### FR-06 AI 执行闭环

**状态：已确认。** 用户下达任务后，运行时可以循环执行「读取必要上下文 → 提出操作 → 宿主检查/授权 → 写入 PTY → 观察结果 → 继续或结束」。普通且满足执行条件的步骤不要求用户逐条点击运行；高风险、缺失凭据、未知状态和权限不足会停在对应步骤。

模型提案不得直接调用 SSH 或本地系统 API。任何工具调用都必须经过宿主边界；命令、输入、结果和是否执行应可区分。

### FR-07 同时只有一个 AI 写入者

**状态：已确认。** 同一实例的多个 AI 任务不可同时向 PTY 写入。非持有者仍可聊天/查看自己的记录，但写入请求应被拒绝或进入清晰的等待状态，不得暗中争抢或自动接管。排队策略、写入权释放时机属于建议基线，由接口文档细化。

此限制只协调 AI 任务；它不会阻止用户手工输入，也不表示获得远端 shell 的独占权。

### FR-08 手工输入由用户协调

**状态：已确认。** 手工键盘输入、粘贴和控制键仍然可用，不建立手工优先、输入抢占或自动暂停/恢复机制。产品应清楚告知：AI 活动期间的手工输入可能被正在运行的程序接收，可能改变目录或提示状态，也可能与 AI 命令拼接。

宿主仍需串行发送传输数据，防止自身并发写入破坏数据结构；这种串行化不能保证 shell 命令语义不混杂。不得将自动检测手工操作作为首版验收前置条件。

### FR-09 破坏性与高风险操作授权

**状态：已确认；识别策略为建议基线。** 破坏性或高风险操作在写入前展示实际目标、操作内容、主要后果和授权范围，由用户批准或拒绝。代表性情况包括批量删除、覆盖重要数据、权限/账户变更、服务中断和向外部目的地发送敏感数据。

授权绑定具体提案及相关执行上下文。目标、命令内容、密钥引用或接收方等实质变化后重新检查；拒绝不执行。规则或模型不能判定风险时进入 FR-10，不能把「没识别到」解释为低风险。风险例子不是完整命令黑名单，也不是安全证明。

### FR-10 不确定状态暂停当前步骤

**状态：已确认。** 无法判断当前输入会交给 shell、交互程序、密码提示还是全屏应用，或无法确认上一条命令是否执行/完成时，应标为未知，暂停依赖该判断的步骤并请用户确认。

标准 SSH PTY 字节流不是逐条 shell 命令的结构化结果接口。不能仅凭输出暂时静默、提示符样式、模型猜测或收到 SSH 写入成功，就认定命令完成/成功。首版允许通过用户确认继续，不要求先实现通用 shell 集成。具体证据与状态见[架构](architecture.md)。

### FR-11 全局模型配置

**状态：已确认。** 模型配置包含 Base URL、API Key、模型名称，由用户在独立本地文件中维护，并独立于 SSH 与任务密钥。模型凭据不进入模型提示词、任务聊天或终端工具参数。配置的存储格式、默认路径和 CLI/环境变量优先级属于建议约定，见[配置文档](configuration.md)。

不得把可填写 Base URL 等同于兼容任意模型服务。协议、流式响应、工具调用和错误处理均需在选定服务上验证。

### FR-12 SSH 配置与凭据单独管理

**状态：已确认；安全存储方式为建议基线。** SSH 主机、端口、用户名、认证方式、软件管理的密码/密钥口令引用和私钥路径归属连接配置。私钥文件内容和连接凭据不供 AI 通用读取；连接配置不与任务密钥文件混写。

主机身份验证不能默认跳过；首次连接与主机密钥变化应明确呈现并处理。首版认证方式、支持的密钥格式和系统安全存储实现需在技术验证中确定。

### FR-13 每任务其他密钥文件

**状态：已确认。** 任务所需的其他密码、令牌等放在该任务独立、用户可编辑的文件中。缺失时，AI/宿主提示用户在指定文件补齐指定键；不得要求粘贴到聊天，也不得将填写文件视为自动批准任意使用或外传。

模型只需要知道密钥是否可用及引用名。宿主在被批准的具体用途边界内解析引用；不提供通用「读取全部密钥」工具。无法安全确定接收程序/目的地时停止该步骤。明文任务文件具有本地泄露风险，应明确告知，并避免日志、版本库和模型上下文收集它。

### FR-14 有界的 AI 上下文

**状态：建议基线，支持自动执行与凭据保护。** AI 上下文由任务消息、有限终端片段、已验证操作记录和必要摘要组成。终端滚动历史、模型上下文和审计记录是不同数据，不把 xterm.js 当前屏幕当作完整真相。

应限定缓冲区、消息大小及模型输入预算；发生截断、遗漏、输出缺口或摘要失真风险时显式标注。不能用摘要替代授权记录或凭据，也不能据缺失的片段声称操作已经成功。

### FR-15 操作与结果可追溯

**状态：已确认；记录结构为建议基线。** 展示 AI 打算执行什么、授权是否通过、是否已发送、观察到了什么及下一步。秘密用引用/遮罩展示；可用的退出码、结束证据和输出范围独立记录，未知值保持未知。

终端输出来自共享会话，可能包含手工操作、后台进程和交互程序输出。没有可靠证据时，只标示「此次观察窗口的输出」，不声称全部输出唯一属于某条命令。

### FR-16 停止、断线和崩溃后的保守恢复

**状态：已确认的安全基线；具体恢复 UI 为建议基线。** 用户可停止 AI 后续规划/发送。已经送到远端的命令不能因此视为已撤销；是否发送 Ctrl-C、其接收对象与效果需要独立处理。取消模型请求也不代表取消远端进程。

断线、超时、写入结果不明或程序崩溃后，未确定结果的操作标为未知，不自动重发命令、凭据或交互答案。重新连接产生新的会话身份；旧授权和旧命令不能不经检查直接复用。

### FR-17 决策模型扩展接口

**状态：已确认的扩展方向，Jev 实现延后。** 保留可插拔的决策接口，供未来判断风险、交互意图、完成证据等。当前不绑定 Jev SDK、协议、版本或部署方式，不声称已有 Jev 集成。

首版只需最小明确状态、基础授权和 unknown/需确认返回路径。后续决策模型只能提出建议，不能绕过宿主的权限、凭据边界或 AI 写入限制。

### FR-18 模型目的地与数据发送确认

**状态：建议安全基线。** 首次向模型发送聊天/终端内容前，应展示实际 Base URL 目的地及将发送的数据类别，让用户确认。更换目的地、从 HTTPS 改为 HTTP 或扩大共享范围时应重新检查确认；不能在失败后静默回退到其他模型服务。

API Key 只作为该服务的认证信息使用。终端内容可能含远端敏感信息，过滤不能保证发现所有秘密；用户应能够在运行任务前理解哪些数据会离开本机。具体规则见[安全文档](security.md)。

## 5. 非功能需求

以下均为**建议工程验收基线**，不表示已经测量或验证。

| 编号 | 主题 | 验收方向 |
| --- | --- | --- |
| NFR-01 | 诚实的状态表达 | 未发送、已发送、已观察、已确认完成和结果未知可区分；未知不是成功，也不自动等于失败 |
| NFR-02 | 凭据边界 | 常规日志、SQLite、聊天上下文及错误报告不含真实秘密；密钥解析只发生在批准用途的宿主路径 |
| NFR-03 | 有界资源 | 终端缓冲、IPC 队列、日志、模型输入、工具循环有预算；超限产生明确状态，不静默丢失关键证据 |
| NFR-04 | 交互可用 | 网络/模型慢或输出量大时，连接状态、停止入口及基本 UI 可响应；量化指标在原型测量后制定 |
| NFR-05 | 并发一致性 | 每个实例只有一个 SSH 生命周期所有者和串行写入口；一个 AI 写入者；多实例不会交叉使用任务凭据 |
| NFR-06 | 可追溯验证 | 需求编号关联验收用例；每次报告区分静态检查、自动测试、Windows 真机测试和未运行项 |
| NFR-07 | 组件可替换 | SSH、模型运行时、存储和决策接口分开；更换库不能绕过宿主检查 |
| NFR-08 | Windows 兼容性 | 在声明支持的 Windows 10/11 x64 环境实测安装、输入法/Unicode、缩放、SSH、断线与卸载 |
| NFR-09 | 依赖与许可 | 固定并记录依赖版本、检查直接/传递依赖许可和发布义务；本项目许可证另行决定 |

## 6. 核心验收场景

以下场景用于建立需求到测试的关系，完整矩阵见[测试文档](testing.md)。

1. **普通任务**（FR-02/04/06/15）：连接服务器，在右侧要求查看一个已知文件夹。观察同一左侧 PTY 的真实输入输出、右侧提案及结果状态。
2. **多任务竞争**（FR-05/07）：两个聊天同时请求写入，只有持有写入权的任务能发送；切换聊天不改变此事实。
3. **手工混入**（FR-08）：AI 活动期间手工输入仍能发送，不触发手工优先状态机；界面不宣称保证没有混杂。
4. **高风险授权**（FR-09）：在隔离测试环境提出破坏性操作，拒绝后零发送；修改原提案后旧批准无效。
5. **未知交互**（FR-10/17）：遇到无法确认的提示、长任务或全屏程序，停止依赖该判断的步骤，给用户明确继续/处理入口。
6. **缺失任务密钥**（FR-11/12/13）：只提示在对应文件补齐指定键；其他任务、模型凭据及 SSH 凭据不被作为替代来源。
7. **不确定断线**（FR-16）：发送过程或发送后断线，恢复时不自动重发；明确显示结果未知。
8. **模型目的地变化**（FR-18）：修改 Base URL 后，未确认前不向新目的地发送上下文或凭据。
9. **大量输出**（FR-14/NFR-03）：超过缓冲/上下文预算时仍可操作 UI，并显示截断/缺口，避免基于缺失数据继续推断成功。

## 7. 尚未冻结的实施选择
