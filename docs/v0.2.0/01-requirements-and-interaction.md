# 01 — 需求与交互

状态：v0.2.0 设计提案，尚未实现。本文只约定产品行为；预算公式和数据契约见 [03](03-token-accounting-and-contracts.md)，压缩机制见 [02](02-context-architecture-and-compaction.md)。

## 1. 目标与边界

让用户像在 Cursor 中一样知道当前上下文用了多少、主要花在哪里，并能自动或手动压缩。借鉴可理解的反馈，不复制复杂面板：继续使用现有聊天、输入框、模型设置和历史记录，不增加常驻仪表盘。

必须同时支持：

- 自动压缩：默认开启，默认使用 LLM 摘要。
- 手动压缩：随时从上下文入口选择 LLM 压缩或快速压缩。
- LLM 压缩：请求当前已授权模型整理上下文，质量优先，有额外模型请求和等待。
- 快速压缩：本地确定性整理，不调用模型，速度优先，可能保留较少细节。
- 上下文占用及类别份额：以实际准备发送的请求为依据，清楚标记估算、未知和上一次供应商实报。

压缩改变后续模型输入，本身不删除可见聊天；历史保留容量另有明确边界。不重跑终端命令，不生成批准，不扩大资料接收方。不把本功能扩展成定价器、跨聊天检索、完整日志归档或新任务执行器。

## 2. 一个入口，逐层展开

输入框工具栏模型名称旁放一个低对比度小按钮，例如“上下文 ≈62%”，配小圆环或短条。正常时中性色，不做持续动画。空间不足时缩短为“≈62%”，保留完整无障碍名称。颜色只是辅助，文字仍说明状态。

常驻百分比表示“可用输入预算占用”：估算输入 /（模型窗口 − 输出预留 − 安全余量），与自动压缩的 80% 阈值使用同一分母。不是类别构成百分比。悬停和无障碍名称注明“可用输入预算占用”；弹层展示预算构成，主界面不展示公式，也不增加另一套窗口百分比。

点击打开小型非模态弹层，从上至下：

1. “下一次请求”及“输入约 24k tokens”；容量已知时显示“窗口 64k”，未知时显示“容量未知”。这些数字仅为文案示例，不是任何模型默认容量。
2. 一条输入类别构成条及最多七行类别，显示估算数量和“占输入”份额。空类别可隐藏。
3. “输出预留”与“安全余量”两行，放在输入构成之外。
4. “自动压缩”开关及当前方式；默认显示“开启 · LLM”。方式选择藏在该行菜单中，可改为“快速”，不另造一组常驻配置。
5. “立即压缩”主按钮，默认 LLM；旁边菜单提供“LLM 压缩”“快速压缩”。手动选择只影响这一次，不暗改自动方式。
6. 折叠“详情”：预算依据、估算方法、上一次主请求实报、最近压缩结果、诊断信息。技术字段和原始错误不铺在主界面。

按钮辅助说明只需“整理后续输入，聊天记录会保留”。LLM 选项说明“使用当前模型生成摘要”；快速选项说明“本地整理，可能丢失较多细节”。不宣称无损压缩。

## 3. 类别文案

| 标签 | 含义 |
| --- | --- |
| 规则与工具 | 系统规则、开发者规则、工具定义和参数 schema |
| 目标与约束 | 当前任务目标、最新明确要求和保留约束 |
| 已有摘要 | 已提交生效的压缩摘要 |
| 对话 | 本次仍携带的用户与模型自然语言消息 |
| 工具与输出 | 工具调用参数、工具结果和实际携带的终端输出 |
| 引用与选文 | 单独携带的证据摘录、选中文本和附件摘录 |
| 其他 | 角色封装、关联标识和无法归入上述项的输入开销 |

分类的是输入中的实际片段，而非界面卡片；同一工具结果不会又按“证据”重复计算。若请求确实复制了同一段文字，则两份实际开销都要体现。分类的完整互斥规则见 03。

## 4. 状态和操作

| 情况 | 紧凑显示 | 操作 |
| --- | --- | --- |
| 正常 | 上下文 ≈62% | 打开弹层；可手动压缩 |
| 未知模型容量 | 上下文 ≈24k | 弹层提示“容量未知”；可手动压缩 |
| 估算暂不可用 | 上下文 — | 明示“暂无法估算”；不能显示 0% |
| 自动触发或手动执行 | 正在压缩… | 可取消；相同聊天不重复启动 |
| 成功 | 恢复普通指示 | 一次短提示“已压缩，聊天记录已保留” |
| 失败 | 压缩未完成 | 保留原上下文；“重试”或明确选择“快速压缩” |
| 保护内容已无法装入预算 | 上下文不足 | 保留草稿；建议减少本次附件/输入或新建聊天 |

压缩成功后，详情显示“输入估算约 42k → 23k”；两者必须是同一请求投影、同一估算器和同一模型预算下的可比数据，不把摘要请求费用或历史总量混进去。没有显著缩减时直接显示“未能进一步缩减”，不伪报成功比例。

生成或终端动作进行中，不抢改在途请求。用户点击手动压缩后，提示“将在本轮结束后压缩”，可取消排队；实际压缩只能在安全检查点执行。若存在执行结果未知、等待审批等更高优先级状态，保留原提示，压缩不能替它完成核对或审批。只读恢复聊天不允许压缩成可执行上下文。

LLM 失败不自动切换为快速压缩，也不自动重试无上限。手动压缩结束后停留在聊天，不自动发草稿、不续跑命令。自动压缩是原已授权模型请求的发送前步骤；它不能绕过运行预算、停止指令、工具审批或终端就绪检查。

## 5. 自动行为与最少设置

已知容量：默认在预计输入达到可用输入预算 80% 时启动；压缩目标为该预算的 50%。若本地传输字节保护先触发，也可自动压缩，但提示“本地请求大小保护”，不伪造 token 百分比。输出预留继承现有最大输出配置。50% 是期望目标；只要按 02 的提交矩阵解除压力且保留保护内容，可以提交并说明“保留信息较多”。压力仍未解除或保护项过大时明确暂停，不能反复压缩同一版本。

未知容量：不从模型名称、OpenAI 兼容协议或一次请求成功猜测窗口。显示“自动压缩待确认容量”，不自动触发 LLM 或快速压缩。仍可做输入估算、字节硬护栏保护和手动 LLM/快速压缩，但不能显示模型剩余百分比或承诺不会超出供应商限制。手动 LLM 仅作有界尝试，模型拒绝超限时安全失败。弹层只提供一项必要入口“设置模型容量”，打开现有模型设置中的“上下文窗口（tokens，可选）”。用户未填不强制阻断原本可运行的请求，迁移后生效的传输字节护栏仍执行。

上下文窗口按提供方地址、模型名称及配置版本关联，切换接收方/模型后重新解析；不能把上一模型容量沿用到新模型。官方可靠元数据可作默认，用户覆盖时注明“手动设置”。超时、阈值、安全余量等高级项折叠，日常不用填写数字。

## 6. 必须保持的体验与安全

- 不添加第二输入框，不强迫用户理解 tokenizer、投影、修订号。
- 点击、键盘 Enter/Space 均可打开弹层；Esc 关闭并返回焦点。百分比和类别有文本可读，色盲及屏幕阅读器可用。
- 编辑草稿只更新本地预览，不向模型发送内容；未授权终端选文不进入发送投影。
- 历史可见性、持久化开关和模型上下文保留是三件事；“聊天保留”不等于全量永远驻留内存或自动落盘。
- 每次压缩有可展开的结果记录，不弹成功确认框，不滚动打断阅读。
- 保留 16 KiB 单消息等独立资源保护；旧 128 条/256 KiB 全局发送限制退役，由上下文预算及独立历史保留策略接管，旧 60 KiB 规划限制由统一预算和审计后的传输字节护栏替代。具体迁移见 02/04。历史页若因独立内存保留上限过期，必须明确标记缺口，不能把“压缩本身保留聊天”说成无限历史承诺。

## 7. 本轮交付判定

用户能在一个入口完成查看占用、查看类别、立即 LLM 压缩、立即快速压缩、切换自动方式；默认自动 LLM 无需额外设置。容量未知、模型切换、压缩失败和在途任务场景均有短而明确的反馈。不得用 UI 文案宣称这些设计已在现版本上线。
