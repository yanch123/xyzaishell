# v0.2.0 上下文架构与压缩协议

状态：设计草案；仅规定后续实现，不代表当前版本已有这些能力。

## 1. 核心决策

1. 上下文是“下一次模型请求实际携带的数据”，不是聊天记录长度，也不是磁盘历史大小。
2. 引入后端拥有的分段账本（ContextLedger）和请求投影（ContextProjection）。压缩只替换投影中的历史表示，不改写用户看到的原始聊天内容。
3. 自动压缩默认使用当前已配置、已获发送许可的同一 provider / destination / model。手动可选“大模型压缩”或“快速压缩”。快速压缩是本地确定性算法，模型请求次数必须为零。
4. 压缩是独立无工具模型请求，不是 terminal_action，不借用 task_context_update 来触发执行，不增加任何终端执行能力。
5. 压缩只能在安全空闲点或规划边界提交。失败、取消、过期、模型配置变化时，旧投影完整保留；绝不悄悄切换快速压缩。
6. 用户目标、约束、当前目标机器、近期完整轮次、在途动作状态，以及引用证据不能被普通裁剪规则吞掉。
7. 压缩摘要是惰性数据。它不能恢复审批、重放命令、重置规划预算、证明成功，或让恢复的历史获得执行权限。

## 2. 已核对的现状与限制

以下是当前源码实际约束，不是 v0.2.0 的 token 预算：

- `crates/xyz-core/src/tasks.rs`：单用户消息 16 KiB、助手文本 64 KiB、对话 128 条及 256 KiB；达到容量时拒绝继续写入/发送，并非自动摘要。普通聊天从消息列表构建请求。
- `crates/xyz-core/src/task_context.rs`：TaskContextSnapshot 绑定 task_id / run_id / SessionRef；最多 16 条 evidence，命令摘要 256 bytes、输出摘要 512 bytes、整体上下文 32 KiB。超过证据数量时新证据不再进入当前列表，并设置 truncated。confirmed_facts 仅表示主机观察到前台返回。
- `crates/xyz-core/src/agent.rs`：规划请求由聊天、task_context、previous_actions、终端窗口等组成；bounded_round_prompt 限制 60 KiB，当前会缩短观察、删除最旧聊天、移除 previous_actions、缩短证据，并设置缺失标记。这不是具有语义保留承诺的压缩。
- `crates/xyz-core/src/model_transport.rs`：请求字节安全上限 1 MiB，另有响应和帧限制；它不能证明请求满足某个模型的 token 窗口。
- `crates/xyz-core/src/history.rs`：历史归档为用户显式启用、已脱敏的可选路径；恢复历史只读。当前隐私边界必须延续。
- 当前请求使用 max_output_tokens，但未形成统一的输入 token 计量、模型容量登记和 provider usage 校准闭环。不得把现有 byte 常量显示为模型 token 容量。

## 3. 四层模型与归属

### 3.1 对话记录 ConversationArchive 与展示分页 TranscriptStore

保存用户和助手的原始可展示消息、执行展示事件，以及压缩操作事件。这里的“原始”指已执行现有脱敏的可保留版本，绝不包含凭据明文副本，也不承诺保留原始 PTY 全量字节。

对话和记忆是两个独立对象：ConversationArchive 在用户启用历史后持久保存脱敏对话，可以保留很久以前的聊天；TranscriptStore 是它的分页展示/内存缓存。模型记忆则是 3.2–3.3 的动态 WorkingMemory，由当前任务状态、相关证据、近期轮次和摘要组成，随任务更新。模型记忆压缩不改写或删除已归档聊天。

分页读取、虚拟列表展示；归档开启时 RAM 页回收只是卸载缓存，SQLite 中已保存的对话不随之删除，仍可按页读取。历史关闭时不存在持久归档，无保护的内存原文可按第 9 节独立保留策略过期，并明确显示缺口。现有默认关闭持久化的选择不改变：本设计不构成自动开启历史保存的许可。只有用户明确启用历史持久化时才允许落盘；磁盘保存期限/配额另按明确的用户策略处理，既不由模型 256K 窗口决定，也不由 RAM 配额决定。压缩不能开启历史存储，也不能将摘要偷偷作为跨会话永久记忆保存。

这里的对话是聊天消息及其展示事件，不是完整原始终端流。终端流/命令日志沿用独立 shell-log 能力、许可与保留策略；对话归档成功不等于全部终端输出已保存。

### 3.2 分段账本 ContextLedger

每个 segment 至少记录：

- segment_id、chat_id、可选 task_id/run_id、session_id/generation、target_identity；
- source_kind、source_ids、sequence、content_revision、redaction_revision；
- content_ref、UTF-8 字节长度、token 估算及算法版本；
- trust（用户输入 / 模型解释 / 不可信工具输出 / 主机生命周期事实）；
- protection（必须保留 / 近期轮次 / 普通历史）、dependency_ids、pair_id；
- completeness（完整 / 截断 / 缺口 / 已移除且不可恢复）、retention_scope。

ledger 是经过脱敏的不可变分段加版本化索引，非凭据存储。引用不等于磁盘地址或可执行对象。输出必须继续标为 untrusted，摘要不能提升其信任级别。

建议 source_kind：system_policy、tool_schema、current_user_input、conversation_history、task_state、terminal_evidence、retrieved_output、compaction_summary、serialization_overhead。以上是来源类型，不是前端计量分类的另一套枚举；必须映射到 03 文档的互斥 category：rules_tools / goal_constraints / summary / dialogue / tools_results / evidence / other。例如 system_policy 与 tool_schema 归 rules_tools，serialization_overhead 归 other；每个实际序列化片段只有一个计量归属，不能同一份内容同时记为“聊天”和“终端”两次；确实重复发送的副本则必须各计一次，以暴露冗余。

### 3.3 动态工作记忆 WorkingMemory 与请求投影 ContextProjection

保存 projection_revision、有序 active_segment_refs、summary_refs、被摘要覆盖的 source ranges、预算快照、遗漏清单。与 03 的拟议接口对齐：外部 PreparedContext 使用 context_revision / config_revision / projection_id 标识快照；context_revision 是 ledger 与有效投影变化统一递增的对外版本，内部仍分别核对 ledger_revision 与 projection_revision。compact_context 接收 expected_context_revision 与 client_request_id，后者用于去重，不能替代版本 fence。构造下一次请求时才将引用解析为最终消息/JSON，不把整个 transcript 再拼回去。

WorkingMemory 仅属于当前聊天/任务及其目标范围，不新增跨聊天、跨服务器的全局记忆。它可以替换过时摘要、更新剩余步骤、移出无关历史；历史事实不自动成为当前服务器事实，涉及当前状态时必须重新验证。读取旧聊天只是展示或显式选择的相关材料，不会自动把整个归档发送模型，也不会恢复审批或自动续跑任务。

同一源范围在 active projection 中只有一种有效表示：原文或摘要。摘要引用关系可追踪到原始 segment；多次压缩形成有界谱系，不重复累加历次摘要。不存在“压缩后 UI 很短、实际仍发送全部聊天”的双轨漏洞。

### 3.4 执行控制 ExecutionState

现有 PreparedAction、审批对象、shell-ready、动作生命周期、取消信号、规划步数仍独立由主机维护。ledger 中仅存只读展示快照，不接收可兑换权限的审批 token、凭据值、可重放 envelope。压缩提交不写此层。

## 4. 预算与计量

### 4.1 两个互不替代的安全检查

- 字节预算：UTF-8 输入、JSON 编码膨胀、脱敏器边界、传输上限、总内存上限。旧上限在迁移阶段保持有效；v0.2.0 发布前按第 9 节明确替换旧全局聊天与规划限制，不能以保留旧门槛阻断新预算机制。
- 模型 token 预算：包括系统提示、工具 schema、消息、证据、摘要、协议包装等实际请求输入，另外预留输出和误差余量。

使用有效容量配置（包括默认值）时定义：

- W = context_window_tokens，产品默认 256K tokens，即十进制 256000 tokens；R = output_reserve_tokens（当前请求最大输出）；S = safety_margin_tokens。容量来源优先级：user_override（用户手动覆盖）> verified_metadata（与当前 provider/model 精确绑定的已验证元数据）> product_default。非法手动覆盖必须报错，不得静默回退到默认值。默认值是本产品预算配置，不代表服务商已证实支持 256K；不得根据别名或自定义 URL 猜测容量。
- B = input_budget_tokens = W - R - S，必须大于零。
- I = 最终请求投影估算的输入 tokens。
- 自动触发指标按当前轮次阶段决定：end_of_turn 时 I / B >= 0.80，active_turn 时 I / B >= 0.95；阶段定义见 6.1。不规定压缩后的固定占比目标，也不要求压缩后低于任一触发阈值。UI 主占用指示器同样采用 I / B，标注为“可用输入预算占用”，与触发条件保持一致；W / R / S 在详情中分项解释，不另设易混淆的整体窗口百分比。类别构成比例采用 I_type / I，与主占用指标分开。
- 建议 S 默认 max(1024, ceil(0.05 × W))；属于保守产品默认值，不是某个 provider 的保证。较小窗口导致 B 不可用时阻止发送，并要求调整输出上限或容量配置，不能静默缩减安全余量。

仅 tokenizer 与模型匹配时称“本地分词估算”；未知 tokenizer 使用版本化保守估算并显示估算范围/可信度。不得将中文字符数、UTF-8 bytes/4 当作精确 tokens。每次请求记住最终投影 hash、模型身份和估算值，成功返回的 provider input usage 用于校准同一模型/序列化路径的误差余量。provider usage 是已完成请求的总量，不能反向伪造每个分类的精确实测量；分类仍是本地估算。缓存命中 tokens 仍占上下文，不从占用中扣除。

普通自定义模型或尚无已验证容量元数据时使用 W=256000、capacity_source=product_default，显示“默认配置 256K，服务商容量未验证”，按该配置估算占用并运行自动压缩；不能仅因元数据缺失而暂停自动压缩。用户可在设置修改容量，所有显示必须区分默认配置、已验证来源与用户覆盖，不能标成服务商实测容量。

只有容量配置不可用/非法，或 W-R-S≤0 时才显示配置错误并暂停自动压缩和依赖该预算的发送，要求修正配置；quick 仍可在本地做有界预览，但不能把无有效 token 预算的结果当成可发送。provider 拒绝 context overflow 时说明实际容量可能与当前默认/覆盖值不同，保留旧投影或已提交投影状态，不猜测服务商真实窗口、不自动改配置、不静默重放原请求；提示用户调整容量后显式重试。byte 安全与本地 token 预算通过均不等于 provider 必定接受。

### 4.2 当前字节界限的延续

v0.2.0 退役旧的固定 60 KiB 规划 prompt 总量限制，统一由模型 token 预算和最终编码请求字节护栏准入；保留当前 transport 1 MiB 请求硬上限，不能绕过 transport 的实际计数方式。系统提示、工具 schema、JSON 转义和包装均计入最终请求体。脱敏器原来的有界处理能力不能因此扩大：须先按受支持大小分块脱敏，保留跨块 secret 匹配的必要重叠与边界检测，再组装请求；跨块匹配测试未通过不得发布该迁移。

常规自动压缩只看 token 指标 I/B 的轮后 80% / 轮中 95%，不设置字节 80% 或 95% 的软触发。即使 request bytes 已接近传输上限，只要未越过硬限制，也不能在 UI token 低占用时偷偷触发压缩。

唯一字节安全例外：有一条已提交、已获现有目的地许可的待发请求，经完整序列化后实际超过 transport 的请求硬限制 L，才允许在安全点按已配置方式压缩或暂停，并明确显示“请求超过本地传输字节上限”。没有待发请求的轮后整理不能由字节大小单独触发。原因枚举统一为 token_pressure / hard_byte_limit / both / manual；both 表示 token 阶段条件满足且待发请求同时超过 byte 硬限制。不得伪造 token 百分比或以近似字节压力绕过该例外条件。

下一请求超过 token 或 byte 硬上限时不得为“继续到本轮结束”强行发送；无法在安全点完成有效整理时暂停提示。自动 job 仍只读取已提交内容，不能为绕开准入把未发送草稿传给模型。不设置任何压缩后固定占比目标；所有提交按 6.5。容量配置非法/不可用时暂停预算依赖的自动流程并提示修正，不把普通无元数据模型当作配置错误。

token 通过而字节不通过、或反之，都不能发送。8 MiB/64 MiB 的历史内存配额不是请求 body 额度。新常量与跨块脱敏路径必须由实现基准、边界测试和安全审查验证；不得仅删除旧检查而不提供替代准入。

## 5. 保留策略与依赖闭包

每轮选择候选前先求不可压缩保护集，再求依赖闭包：

- 当前用户请求、仍生效的目标与用户约束、明确否定/纠正、当前 target identity 与会话 generation。
- 最近两个完整的用户—助手轮次；未完成的流式消息单独保护，不算完整轮次。
- live action、待审批动作、未闭合 tool-call / result 对、结果未知的执行记录。保护其主机状态与引用，不把审批票据放入请求。
- 用户显式保留的内容、仍被当前事实/步骤引用的证据锚点。
- 所有工具调用与结果按组选择或排除，不得产生孤立 tool result 或伪造 result；当前 JSON 规划格式同样适用语义配对。

“保护”不是无限额度。保护集自身超过任一预算时返回 CONTEXT_PROTECTED_OVERFLOW，说明哪些类别占用过大，要求用户缩小当前输入、取消/结束挂起状态或开新会话；不得偷偷删目标、最近轮次或证据。原始长证据可以转为带缺失标记的短锚点，但必须保留引用可解析性、主机状态、缺失性质，不宣称内容完整。

## 6. 大模型压缩流程

### 6.1 触发和快照

“一轮对话结束”指本次用户请求的最终助手回复已完整发出，并由主机明确关闭该轮；不是每个模型响应结束，也不是整个聊天归档关闭。

- active_turn：用户消息已提交且本轮尚未最终关闭，包括分析、工具调用链、流式回复、命令等待返回、等待审批/密码、规划预算暂停或执行结果未知。此阶段占用 80%–不足 95% 时继续原有获授权流程，不触发自动压缩；达到 95% 才登记自动压缩需要。
- end_of_turn：最终用户可见回复已完整发出，且没有本轮未结清的模型流、工具/命令、审批或秘密输入等待。此时占用达到 80% 才启动轮后自动压缩。预算暂停、工具响应、暂时停顿不构成结束；失败/取消保留单独的停止或核对状态，不因运行进入终态就触发轮后 80% 压缩，也不能从文本措辞猜测；用户停止后不得另起自动摘要请求。

检查点为最终回复发完后的安全点，以及 active_turn 当前模型流/工具执行完成、下一次模型规划前的安全点。占用依据裁剪前的完整候选投影计量，不对旧 cap 截短结果测量。达到 95% 不得中断正在进行的模型流或已派发命令：仅登记一次请求，等待该步骤正常结束、主机确认无在途执行并满足 shell-ready 等现有条件后再快照。命令仍在途或结果未知时保持等待/阻塞，绝不伪造 ready。

用户输入框草稿只允许本地占用预览；自动 job 的源集合只能是已提交并具有现有目的地发送许可的内容，不因预览触发外部模型调用。新消息正式提交后进入 active_turn，使用 95% 门槛；提交前须做硬预算准入，超限不能强发。轮后压缩尚在运行时到达新消息，应取消并通过 revision/cancellation fence 作废旧 job，按新 active_turn 状态重新评估；不能将旧 80% job 当作新轮任务继续提交。

采用 6.5 的可压缩来源指纹和尝试记录防循环；阶段或指标变化本身不构成新增可压缩内容。每个 checkpoint 只允许一个 job。手动压缩仍可主动选择方式，空闲时执行，忙碌时可登记一次“下一个安全点执行”并取消；不受自动 80%/95% 门槛限制，但同样不能打断模型流、命令或审批提交。等待审批时不处理压缩，用户可取消审批后进入安全点。

job 快照字段：job_id、chat_id、turn_id、trigger_phase、phase_revision、task_id/run_id、session generation、target fingerprint、ledger_revision、projection_revision、config_revision、authorized_destination、model、redaction_revision、cancellation_epoch、source_set_hash。配置快照只引用现有凭据安全句柄，不复制 API key 到 job、日志、历史或前端事件。

### 6.2 压缩请求自己必须能装下

1. 分离保护集与可压缩旧段，先以实际序列化大小和 token 估算做预检。
2. 压缩提示自身、摘要输出预留、引用 manifest、源材料均计入压缩请求预算；不能把已经溢出的主请求原样发送给“压缩模型”。
3. 候选大于预算时按完整轮次/工具对切分为有界块，顺序生成结构化局部摘要，再有界合并。块之间带全局目标/约束锚点和稳定 source IDs；不得把未输入的内容记成“已覆盖”。
4. 单段超过预算时按 UTF-8 边界和证据页切分；不可分保护集超限则失败。截断材料必须记录 omitted_ranges / truncation，不把缺失当作空输出。
5. 建议每 job 最大 8 次模型请求（含合并）、总超时 120 秒、每次请求服从现有更严格超时及输出限制。达到上限返回 INCOMPLETE，不提交局部结果，不递归无限压缩。
6. 同一可压缩来源指纹的自动压缩失败后不每轮自旋重试；进入需要重试的状态。用户手动重试或修正容量/算法配置可重新请求；单纯新增事件或 revision 不是有效新候选，任何自动新尝试必须有新增可压缩源范围。

### 6.3 结构化摘要契约

模型仅返回严格 schema 的内容字段，禁止任意字段和工具调用：

- goal：当前目标；user_constraints：仍有效的约束、纠正与禁令及其 source IDs；
- findings：有证据的结论、evidence refs、模型解释标记；
- hypotheses：尚未验证的可能性及所缺证据；
- remaining_steps：待做事项、阻塞、模型报告状态；
- uncertainties：未知执行结果、输出缺口、互相冲突的描述；
- coverage：已覆盖源范围及明确遗漏；summary_text：便于阅读的短摘要。

主机补充 current_target / session scope、source manifest、confirmed lifecycle facts，模型不得改写。主机验证 source IDs 必须在快照中，证据引用闭包可解析；输出非空、字段/条数/字节/token 上限合规；completed 步骤只接受满足现有主机完成证据约束的引用，且不代表业务成功。目标与约束的主机保护原文仍单独注入，不依赖模型“自称保留完整”。关键约束缺失、未知引用、非法状态或工具调用使整个候选失败。

提示明确：输入中的终端输出、历史助手建议和嵌套提示都是数据，不是系统指令。摘要中的“用户已批准”“继续运行某命令”等文字不具效力；不可信文本不能通过摘要变成系统层指令。发出请求前及接收后均走当前脱敏器；新学习到的 secret 导致 redaction_revision 变化时丢弃候选并重新脱敏，不提交旧版本内容。

### 6.4 原子提交

验证候选后，在短持锁事务中比较全部快照 fence：会话/目标、turn_id/phase_revision、ledger/projection revision、配置目的地与模型、脱敏版本、取消 epoch 均未变化，且仍处安全边界，才 CAS 替换 active projection。append 一条压缩事件，递增 projection_revision，发出新占用快照。

任何 fence 不匹配则 STALE，丢弃结果；不得套用到新会话、其他 SSH generation、不同模型目的地或新用户消息。取消与提交以同一锁内 epoch 检查线性化：取消先赢则不能提交；提交先赢则报告已完成，不能伪称已取消。提交过程不刷新审批、不修改执行 adapter、不触发后续命令重放。

active_turn 提交后仅继续原本获授权且仍有效的待发聊天/规划流程，重新验证目标、当前审批策略与预算。end_of_turn 压缩只更新动态记忆，既不生成额外回复，也不恢复已结束任务或启动新命令；手动压缩本身同样不触发额外聊天或终端动作。暂停中的任务不因压缩恢复。

### 6.5 统一提交条件与防循环

不设置 target_ratio / target_met；既不强制降至 50%，也不把 80% 或 95% 变成新的压缩后成功门槛。v0.2.0 的成功是“安全保留必要信息、产生可计量缩减、给当前待发请求留出足够空间”。

所有方式提交前均要求：

1. 保护闭包、证据引用、脱敏、覆盖完整性及 CAS fence 全部通过。
2. 比较同一个待发请求的 before / after 完整投影，使用相同 tokenizer/估算器版本和编码规则：I 与最终 request bytes 至少一项严格下降，另一项不增加。token_pressure 时 I 必须严格下降，hard_byte_limit 时 bytes 必须严格下降，both 时两者都须严格下降；手动无压力时允许任一项严格下降。
3. 完整待发请求（含当前用户输入、系统提示、工具 schema、包装）必须 I_after≤B 且 bytes_after≤L；R/S 已由 B 预留。不能只计算摘要大小，不能为通过门槛删除保护内容。即便 I_after/B 仍为 85%，只要真实缩减且完整请求满足硬护栏，也可以提交。
4. 没有待发请求的手动压缩按当前完整候选投影计算，后续新增输入仍需重新准入。容量配置非法/不可用不能报告可发送成功，要求先修正。

无缩减返回 no_effect，保护/证据校验失败返回 failed，缩减后仍不够容纳当前待发请求返回 needs_adjustment；均保留旧投影，不自动连续调用模型追逐某个百分比。needs_adjustment 是 failed 的原因码；skipped_no_new_content 是未创建新 job 的检查结果，不是可执行状态。UI 展示实际前后 tokens / bytes、保留内容与缺失，不展示“目标占比未达标”。

防立即重复压缩采用可压缩来源与覆盖指纹：eligible_source_fingerprint = 对候选源 segment IDs、内容版本、已覆盖源范围、保护集合版本和算法/配置版本的稳定摘要。每 job 记录 attempt memo（fingerprint、结果、被覆盖范围）；提交时同时写入 coverage ledger，将新摘要视为已覆盖来源表示。压缩事件、projection revision、计量刷新或摘要自身新 ID 不构成新的可压缩内容，不得因此再次调用模型。只有出现此前未压缩且已离开保护窗口的源范围，才可在自动阈值仍满足时生成新的自动 job；否则 skipped_no_new_content。即使摘要仍占 80% 以上也不对相同源覆盖循环压缩。用户显式重试允许再次处理同一覆盖范围，但仍受 job 上限、取消和所有准入检查约束。

配置变更作废旧快照并重新计量；预算收紧到无法容纳时需要用户处理或显式重试，不能仅通过更换 revision 绕开同源自动尝试去重。最终 provider 仍可能因默认容量不符拒绝请求，按第 8 节停止并提示调整。

## 7. 快速压缩：本地、可复现、可解释

输入为同一快照，输出使用相同投影提交协议。算法固定排序（sequence、segment_id），同输入/版本应得同输出：

1. 原样保留保护集及引用闭包。
2. 对旧 terminal_evidence 删除精确重复行、折叠连续重复；保留有界头尾、主机生命周期元数据和被引用的证据锚点；任何删除都写入省略计数/范围。只识别明确结构，不推断“成功/失败”。
3. 旧聊天按完整轮次保留确定性首尾摘录；超额部分移出 active projection，并生成指向原始记录的有界目录和缺失标记。不是删除 transcript。
4. 已有已验证结构化任务状态可原样复用；不得用正则从散文发明新的目标、事实或完成状态。不存在结构化状态时使用“历史摘录/省略目录”，不冒充语义摘要。
5. 重新计量并按 6.5 的统一提交条件判断；满足提交条件才原子提交。没有节省、保护集太大或无法解除必要压力时返回具体原因，不提交一个声称成功却仍不能发送的结果。

快速压缩可能丢失措辞细节和跨轮推理，界面需明示；它无需 provider 网络访问、不会使用另一个便宜模型，也不会执行命令。单次手动选择 quick，或用户明确把自动方式设为 quick，才授权相应的快速任务。全部自动触发原因均遵守保存的自动方式，不因字节压力改回 LLM。LLM 失败只展示重试/快速压缩/取消选项，等待选择，不静默回退。

## 8. 状态机、失败与调度

状态：idle → requested → waiting_safe_point → snapshotting → estimating → compressing（LLM）/ reducing（quick）→ validating → committing → succeeded。任何阶段可进入 cancelled、stale、failed、no_effect；这些终态保留旧投影，succeeded 除外。

- 网络/鉴权/限流/超时/模型拒绝/JSON 错误：旧上下文保留，显示原因与重试入口。不得携带用户上下文自动改发其他 provider。
- provider context overflow：记录当前配置预算与实际接受能力可能不符，停止该请求，提示检查默认 256K 或用户覆盖值。不得据错误信息臆造精确窗口、自动改变容量、静默重放原请求或另发模型请求猜测界限；调整容量后由用户明确重试。候选尚未提交时保留旧投影；主请求在提交后被拒绝时保留已提交投影，不伪称请求成功。
- 当前主请求尚可容纳但压缩失败：允许用户选择使用未压缩投影继续，并再次预检；已经超过硬上限时必须阻止发送。
- 压缩结果比原文更大、覆盖不足或保护项遗漏：失败而不是“压缩完成”。不设固定压缩后比例，只有符合 6.5 的缩减、保护与完整请求准入条件才提交。当前请求仍超硬预算时暂停并保留旧投影，不在后台连续多轮调用。
- 取消/关闭会话/切换目标/配置修改：取消对应 job，迟到返回只能销毁，不能恢复 UI 状态或执行状态。
- 压缩请求有自己的并发许可与 job 计数；不占用终端 action 配额，既不清零每批 16 次规划计数，也不清零每个运行累计 256 次上限。每聊天最多 1 个压缩任务，总并发建议 1，避免压缩挤占全部聊天额度。

## 9. 存储、迁移与兼容

### 9.1 从 128 条聊天限制迁移

不能只把 MAX_MESSAGES 调大或压缩后删除 messages。先拆分展示分页与 active projection，再退役“128 条 / 256 KiB”为整个聊天的发送拒绝门槛；128 条可作为展示分页上限，256 KiB 可作为分页 byte 目标，均不得继续限制整个 live 会话。发送只由当前投影 token / byte 准入和保护项安全条件决定。

拟定有界内存默认值为每聊天 8 MiB、进程上下文存储总计 64 MiB（包含 ledger、原始页、摘要、索引及引用锚点；估算必须计入结构开销，不能只累计字符串长度）。新常量是实现前基准测试的初始设计值，需验证多会话、重复压缩、并发快照与峰值临时分配；job 输入/输出同样占独立受限暂存预算，不得借复制快照无限超额。

RAM 回收策略独立于压缩提交，也独立于磁盘归档保留策略：

- 仅回收“已经由已提交摘要覆盖、当前投影不再引用、无保护依赖”的原始页，按最旧优先。压缩成功本身不立即删除原文；触及 RAM 配额才触发独立保留事件。
- 当前目标、有效用户约束、现用摘要、最近保护轮次、未闭合 tool pairs、live actions、未决审批展示引用、已引用证据锚点及其依赖闭包不可回收。不能为了腾内存破坏当前任务的解释能力或动作关联。
- 历史存储关闭时，允许这些旧原始页从内存过期，但必须保留有界 source tombstone/缺口范围，并提示“部分早期原文已过期，仅保留摘要”。不能偷偷写 SQLite、临时文件或其他磁盘缓存。旧输出明确标为 expired，不能当成空输出或可恢复记录。
- 历史存储开启时，已确认归档成功的原始页可以卸载 RAM，SQLite 记录仍保留并可分页读回；这不是历史删除，不记录为不可恢复缺口。归档失败或磁盘配额不足时停止新增归档并立即标记“未保存”，保留已保存旧聊天；不得静默删除旧归档腾空间。未保存页不能伪称可恢复，也不能自动套用“历史关闭”策略悄悄丢弃；RAM 不足时暂停会继续增长的操作，提示用户解决存储或明确选择后续处理。读回历史不自动注入模型请求，也不恢复执行权限。
- 若可回收页不足、保护集合本身超过单会话或全局限额，保留当前状态并阻止会导致超额的新操作，提示结束其他会话、缩小输入或开新会话；不静默丢保护内容。不会为腾内存自动结束在途命令。全局回收可选其他会话已压缩无保护页；已归档页仅记录缓存卸载，无归档且按策略实际过期的页才记录可见过期事件。
- tombstone 按连续范围合并，摘要谱系和压缩事件分页/有界保留，不能把“元数据很小”当作无限增长豁免。仍被保护项引用的 ID 必须可解析，其余过期 ID 可由区间 tombstone 解释。

当前 `persistence.rs` 还把归档与 MAX_MESSAGES/MAX_TRANSCRIPT_BYTES 绑定，并设有 32 MiB 数据库、2 MiB payload 与 MAX_CHATS 的防护。这些不是模型记忆限制，也不是长期对话保留政策。实现须迁移为版本化消息页/索引：旧 128 条 / 256 KiB 只作为兼容页约束，不能继续限制整个归档聊天；32 MiB 现有磁盘防护可以作为迁移期独立容量边界，但满额必须报告并停止新增归档，不能删旧记录或谎称已保存。扩大磁盘额度、保留期限、主动删除均需独立明确用户策略与测试，不承诺无限磁盘。

持久化开启时新增版本化 segment/summary 索引及分页读取；写入只能使用已脱敏数据，按现有显式授权和删除策略执行。旧归档迁移为只读 transcript，不能自动选入新 live projection。压缩记录不保存认证票据。此设计支持持续压缩后的长任务，但不承诺无限原始历史。

### 9.2 从 16 条证据限制迁移

原 MAX_EVIDENCE 不再代表“整个任务只能记住前 16 条”。拆分为有界证据库和请求证据选择集：持续接收已脱敏证据，按 byte 配额保留；请求优先选择当前引用、近期及未闭合记录，并压缩旧引用为稳定锚点。16 可暂作兼容 UI 单页数量，不可继续静默拒收第 17 条而仍宣称摘要覆盖完整。

每个引用必须指向 live evidence、保留的脱敏锚点或明确 tombstone。配额回收不可移除未闭合动作和关键引用闭包；空间不足就暂停新增计划，不能伪造证据。原来已经丢失的输出不可恢复，迁移时保持 truncated/gap；绝不重跑命令补齐历史。

### 9.3 替换旧的隐式 prompt 裁剪

bounded_round_prompt 的最终安全校验职责迁入统一 ProjectionBuilder；原固定 60 KiB 与静默删老对话策略一起退役，以模型预算、transport byte 护栏、显式压缩/遗漏事件替代。开发迁移阶段可保留旧检查，但只有替代准入、跨块脱敏、语义保护与工具配对测试全部通过后才切换并发布，不能发布一套仍被旧 cap 提前阻断的“轮后 80% / 轮中 95% 自动压缩”。普通聊天与终端规划共用预算/压缩基础设施，但各自保留不同的执行边界、系统提示及可发送内容范围。

## 10. 必须覆盖的验收测试

- 同一长对话分别手动 LLM、手动 quick、自动 LLM：原始展示记录不变，active projection 缩减，分类占用总和等于实际发送投影估算。
- 中文、emoji、多字节边界、JSON 转义、超长一行输出、重复日志：不切坏 UTF-8，不绕过 byte 限额，不把 byte 当 token。
- 第 17 条证据可参与事实引用；128 条 / 256 KiB 以上仍可在投影准入后发送；分页不破坏顺序与引用。8 MiB/chat、64 MiB/process 压力下只回收已压缩无保护页，产生可见缺口；保护集合无可回收空间时安全阻止增长。
- 大于模型窗口的输入必须分块，所有块及合并请求均预检；8 次/120 秒上限、无收益摘要及单段超限均安全退出。
- 模型幻造引用、把假设转事实、声称已审批、输出工具调用、提示注入：拒绝或保持原信任类型，执行器调用次数为零。
- 快速压缩断网运行成功，provider mock 请求计数为零；LLM 失败后 quick 计数仍为零。
- 压缩中取消、到达新消息、会话关闭、SSH 重连、目的地/model 修改、secret 新增：旧 job 无法提交；旧投影仍可读。
- 主机命令在途、等待审批、流式回复时只排队，未闭合 tool pair 不可裁剪；压缩不会制造 shell-ready、重置规划步数或重复发命令。
- 关历史存储后压缩与原始页回收均不落盘；开启后仅脱敏内容持久化，归档成功页卸载 RAM 后仍可读回，压缩前后已归档聊天内容不变；磁盘满额/归档失败停止新增归档并标未保存，绝不静默删旧归档。未归档原文过期与引用 tombstone 可辨别。恢复归档仍只读，不能恢复审批或继续旧命令。
- 大窗口下超过旧 60 KiB 仍能按新预算安全运行；byte 占用80%/95%但未超硬限制时不单独触发；已提交待发请求确实超传输硬限制时才以hard_byte_limit例外处理并明确展示，无容量元数据时使用标明来源的默认 256K 正常评估自动触发；分块脱敏覆盖跨块秘密、UTF-8、JSON 转义，transport 1 MiB 不能被绕过。
- 无容量元数据时 W=256000 且标注 product_default，不能伪称服务商已支持；用户覆盖优先于精确绑定的验证元数据，验证元数据优先于默认。非法/不可用容量暂停预算依赖流程；provider overflow 不猜容量或静默重放；usage 缺失不填零；模型切换后校准不串用；缓存计费折扣不减少容量显示。

- 压缩后仍为 85% 但严格缩减且待发请求通过硬护栏时可提交；没有固定占比达标检查。提交事件/revision/新摘要 ID 不触发同源再次压缩，无新增可压缩源范围时跳过模型调用；实际新增可压缩源范围才允许新的自动尝试。

- active_turn 的80%、94.9%不自动压缩，95%登记并等待安全点；end_of_turn达到80%在最终回复发完后整理。工具响应/等待审批/密码/预算暂停不得误判为结束；在途命令不得打断。轮后整理期间新消息使旧job失效并切到95%门槛；输入框草稿预览不得发出模型请求；硬超限始终阻止发送。

## 11. 已定产品取舍与实现验证项

对话归档与动态记忆分离：已启用归档可按独立磁盘策略长期保存旧对话，压缩和 RAM 页回收均不删除已归档内容。长任务不再受旧 128 条 / 256 KiB 全局发送限制；关闭历史时旧无保护内存原文允许可见过期，绝不隐式落盘。近期保护两完整轮、8 次模型请求 / 120 秒作业、8 MiB 单聊天 / 64 MiB 进程 RAM、默认 256K tokens（256000）与轮后 80% / 轮中 95% 自动触发均为可测试的初始设计默认值；不设压缩后固定占比目标，需要真实模型、中文/日志长输入、多会话和峰值内存基准验证。常量调整不改变安全不变量：保护内容不能静默过期，旧权限不能恢复，默认容量来源必须明示，不能伪造服务商真实容量，失败不得偷偷切快速模式。
