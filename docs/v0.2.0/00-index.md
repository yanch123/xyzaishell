# 00 — v0.2.0 上下文管理设计

状态：**开发中，尚未发布**。日期：2026-10-17（UTC+8）。基线：已发布 v0.1.4，程序源码 `0e29b1e5912f35e9eabd73ac073524af143cd622`。本目录定义 v0.2.0 的开发与验收要求；已发布的 v0.1.4 保持不变。

## 1. 用户看到的变化

输入框附近增加一个简洁的上下文占用指示，点击后看分类占比与压缩操作。正常使用只需继续聊天；按回合阶段在达到阈值时自动整理：正在进行的任务在安全点整理后继续，已经结束的回合整理后等待用户新输入。

- **自动压缩**：默认开启，默认使用大模型压缩；可以在弹层中明确改用快速模式。
- **手动压缩**：随时发起请求，选择“大模型压缩”或“快速压缩”；在安全边界执行。
- **大模型压缩**：调用当前配置的模型整理旧上下文，保留目标、用户约束、发现与证据、待确认事项和剩余步骤。会产生额外模型调用。
- **快速压缩**：本地按确定性规则去重、筛选与缩短旧内容，不调用模型。速度快，但不能代替语义总结，也不是无损压缩。
- **占用与分类**：显示下一次请求的估算输入占用；展开查看固定规则／工具定义、目标与约束、任务摘要、聊天、工具执行记录、终端输出／证据、其他开销。
- **压缩记录**：显示方式、原因、前后估算占用、整理结果或失败原因；不把估算节省量当作实际账单节省。

界面借鉴用户提出的 Cursor 式轻量入口，不照搬其实现，不要求用户理解内部状态机。日常界面不展开大量设计说明或调参项。

## 对话记录与动态记忆分开

- **对话记录**保存用户与 AI 的聊天原文。开启历史保存后，可长期存储在本地并按需翻阅；模型窗口大小、上下文压缩和内存分页回收不能删除或改写已保存的旧对话。
- **动态工作记忆**保存当前任务要带给模型的目标、约束、摘要、证据和近期内容，随任务变化而更新、筛选和压缩；模型每次只接收选中的这一部分。
- 长期归档、内存显示缓存、模型输入是三套独立管理对象。打开旧聊天页不等于把全部旧记录重新发给模型。磁盘保留策略与容量独立设置，不以模型 token 预算决定历史存多久。
- 历史保存沿用现有开关，默认关闭；未开启时不偷偷落盘，也不能承诺关闭程序后仍保留聊天。历史写入失败要提示，不能静默删除旧对话来让新内容看似保存成功。
- 聊天原文不等于全部终端原始输出；终端操作日志仍独立管理。这里的“记忆”指当前聊天／任务的工作记忆，不新增跨服务器共享记忆或恢复旧执行权限。

## 2. 默认策略

| 项目 | 设计默认 |
| --- | --- |
| 自动压缩 | 开启，使用大模型模式 |
| 手动入口 | 占用指示弹层中的“立即压缩”，可选两种方式 |
| 默认模型窗口 | 256K tokens（十进制 K，即 256000 tokens），可修改；注明容量来源 |
| 输入预算 | 配置的模型窗口减输出预留与安全余量 |
| 本轮结束后 | AI 最终回复发送完成且主机关闭本轮后，已提交上下文占用达到 80% 时自动压缩 |
| 本轮进行中 | 分析／执行仍在继续时，达到 95% 才在安全检查点压缩；80%～95% 继续正常处理 |
| 硬上限保护 | 待发请求实际超过 token／传输字节硬上限时不能强发；安全整理或暂停，并明确说明原因 |
| 整理目标 | 保留必要信息、实际减少冗余、为后续交互腾出空间；不设固定压缩后百分比 |
| 常驻占用指标 | 估算输入 / 可用输入预算，和自动触发使用同一分母 |
| 分类占比 | 某类输入 / 全部输入，与总预算占用明确区分 |
| 默认压缩模型 | 当前聊天配置的同一模型和服务，不新增一套密钥配置 |
| 模型压缩失败 | 保留原上下文，不静默切换快速模式，不反复自动重试同一快照 |
| 无可靠模型容量信息 | 使用默认 256K 配置，显示“按默认容量估算”；不宣称供应商实际支持该窗口 |

256K 是用户指定的产品默认配置，不是 256 KiB 聊天存储限制。手动配置优先，其次使用有可靠来源的模型容量信息，否则采用该默认值。若实际服务拒绝上下文过长，应暂停并提示调整容量，不猜测真实上限或盲目重发。80%／95% 只决定相应阶段何时考虑自动整理，不是整理后的达标比例。一次工具调用返回、等待危险授权／密码或规划预算暂停，都不等于本轮对话结束；正在流式响应或执行的命令不被压缩打断。回合结束后的整理不会重新启动终端操作；新用户消息使旧的轮后压缩快照失效，并切换到轮中规则。未发送草稿只用于本地预估，不因自动整理被发给模型。没有新可压缩内容时不反复调用模型。

以上是待实施与测试验证的产品默认值，不是 Cursor 的参数，也不是模型供应商的能力声明。高层流程保持自然语言目标 → 命令 → 结果 → 后续操作；本版只改善它使用上下文的方式。

## 3. 压缩必须保护的内容

1. 系统规则、工具定义与执行约束仍由程序提供，不交给模型改写后替代。
2. 当前用户目标、关键限制、目标服务器身份、当前未完成事项和最近必要对话保持完整。
3. 命令实际执行事实、退出码、来源和时间与模型推测分开。摘要不能将“猜测”变成“已确认”，不能将退出码 0 变成业务成功。
4. 未完成工具调用与对应结果不能拆散；危险命令授权、连接身份和不确定执行状态不能由摘要重建或继承为新权限。
5. 压缩只整理已经拥有的资料，不执行 Shell、不补跑旧命令、不把缺失输出编造成已读取。
6. 压缩成功后原子替换模型输入投影；失败、取消或快照过期时保留原状态。聊天显示记录和是否落盘由独立保留策略控制。

例如查询容器日志时，整理后仍应知道用户要查哪个服务、容器如何定位、已经看过哪些日志、发现来自什么证据、哪些判断尚未证实、下一步要检查什么；不能只剩“已检查日志”一句话。

## 4. 本版必须一起解决的旧限制

v0.1.4 的摘要主要靠模型主动更新，并依靠固定字节裁剪；这不等于自动语义压缩。

v0.2.0 必须同时迁移原有 128 条消息／256 KiB 全局拒绝门槛、60 KiB 规划内容上限以及只保留最早 16 条命令证据的行为。否则界面虽然有“压缩”，长聊天仍可能在达到模型预算之前被旧限制拦住。

迁移采用有界、分层存储与上下文投影：历史分页、摘要和证据索引分别管理；关闭历史保存时不得偷偷写磁盘。已压缩且不再受保护的旧原文达到独立内存保留上限后可过期，必须标明缺口；当前目标和必要证据不能因此静默丢失。达到全受保护内容的真实上限时应说明限制，不承诺无限历史。
